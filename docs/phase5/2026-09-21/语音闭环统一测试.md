# Phase 5｜语音闭环统一测试

## 当前链路与边界

正式运行的级联链路为 Room 16kHz PCM → Qwen-Audio Realtime（ASR / smart_turn）→ 外置 LLM → **每轮一个 Qwen-TTS duplex task** → 同一份 24kHz PCM → reb_tts。网页试听只消费 Room，不生成第二份 TTS；ForcedAligner 旁路只听真实 PCM。

每轮 TTS 仅发送一次 run-task，按序多次 continue-task，LLM 完成时发送一次 finish-task；Provider 的 PCM 接收与 Room 发布时钟分开，Room 包序号、sample cursor、stream_epoch 不变。**一轮一个声学 segment**：reb_tts.data.turn_id 固定为 `<conversation_id>-1`，`data.text` 为已提交 TTS 文本的累计值；不能将文字提交时刻冒充字词的真实声学边界。零音频的 segment-final 才向 ForcedAligner 表示该轮文本/PCM 完结，然后发布 stream_final。只有 ForcedAligner 产生的真实样本边界可当嘴型时间。

## 物理扬声器 Hold/Resume 协议

Runtime 向**所属机器人的 reb_tts**发布：

```json
{"type":"tts.playback.hold","ts":0,"data":{"protocol_version":1,"conversation_id":"turn-a","stream_epoch":1,"command_seq":1,"reason":"speech_started"}}
```

无效轮次 `turn_invalid` 发布同结构的 `tts.playback.resume`，新的 `command_seq` 严格递增。有效 ASR final 则沿用 `type:"tts",data.stop:true` 的终止帧，不再恢复旧轮。设备必须在自己的音频播放线程冻结采样游标且**不裁剪等待期间的 PCM**；Resume 从冻结游标恢复；有效打断清掉旧轮缓存。设备不能仅凭收到控制命令就声明已暂停或恢复。

设备实际应用 Hold 后，向同 Room 的 **reb_main** 发布 `tts.playback.held`，实际应用 Resume 后发布 `tts.playback.resumed`。示例：

```json
{"type":"tts.playback.held","data":{"protocol_version":1,"conversation_id":"turn-a","stream_epoch":1,"command_seq":1,"played_sample_count":480,"sample_rate":24000,"seq":2,"source":"speaker","playback_id":"device-a-1"}}
```

Resume 回执结构相同，`command_seq` 回显对应 Resume 指令，`seq` 是该扬声器回执的递增序号；`played_sample_count` 为实际已消费 PCM 样本数，暂停与恢复之间不得倒退或虚增。旧轮次、乱序、重复和浏览器伪造的 held/resumed 都不升级为真机确认。已存在的 started/progress/drained/stopped 回执继续沿用；网页监听**不代发 source=speaker**。

目前仓库可验证的是**命令发送、身份校验、设备回执状态机**；未接入实体扬声器的控制执行代码，真机执行/停止/嘴型同步仍需设备端按协议实现并实测。

## 延迟数据契约

服务端同一 `turn_id` 记录 `speech_started_ms → speech_stopped_ms → asr_final_ms → llm_request_ms → llm_first_text_ms → tts_submit_ms → tts_first_pcm_ms → room_first_publish_ms → speaker_started_ms`。缺失的阶段返回 null，不用 0 代替。最后一项是**服务端收到 speaker.started 回执的时刻**，包括回执返程延迟，不等于 DAC 实际起播时刻。网页试听、Room 首发布不得冒充物理播放。P50/P95 只对当前机器人的最近 32 轮有真实 speaker.started 的停声→回执样本计算，并展示样本数；没有样本则显示未测。文字输入没有 speech_stopped，不能参与该端到端分位数。

## 自动化与人工验收

自动化：

```sh
.venv/bin/python -m pytest -q
npm --prefix web run build
npm --prefix web test
node web/tests/microphone.browser.mjs
node web/tests/room-debug-speaker.browser.mjs
git status --short
```

浏览器测试使用模拟 Room、真实浏览器 AudioWorklet，不向真 Room 发测试音频；单测/模拟通过不填写物理验收通过。

人工测试时，同 Room **只能有一路麦克风**；先关麦耳机试听，再开麦耳机试听，再开麦外放，始终用同一段人声 PCM 和同一音量观察断粮、回声误触发。检查起声暂停→噪声误判无损续播、有效插话清旧缓存、连续三句话无段间重启、ASR delta/final/ambient 顺序、空闲超过 180s 的自动恢复、两个 Room 独立运行、ForcedAligner 样本对齐、真实设备 started/held/resumed/stopped/drained 回执。最后记录延迟 P50/P95 样本数和真实听感。任何缺项保持待验，**不以日志/测试绿灯代替实体设备验收**。
