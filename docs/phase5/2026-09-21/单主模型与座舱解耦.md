# Phase 5｜单主模型与工作台解耦

## 本次实现

- 普通对话统一使用 `qwen-audio-3.0-realtime-flash` 的原生文本与 Function Calling；`session.update` 采用 `modalities=["text"]`、`smart_turn`、Preview 工具。保留独立 TTS→Room PCM→ForcedAligner 嘴型链路，不恢复模型内置语音双播。
- 删除启动器的 Cascade 默认启用逻辑、额外 Chat HTTP 流式 Adapter、两套回复任务及专为 Cascade 服务的闲置保活/状态。原生 Realtime ASR 与生成属于一个 Provider Session；仅经必要工具回写后继续同一模型回复。
- 保留旧 response/item 归属、打断清理与设备起停播证据；新的 ASR 最终稿不得覆盖上轮已完成的用户文本，也不得把本轮刚开始的回答误判成旧音频取消。
- React 中麦克风电平、播放缓冲各在独立组件内更新；普通诊断 SSE 不再在抽屉关闭时更新主组件。开发者抽屉与场景复跑状态、延迟面板各自独立；完整会话/Persona/机器归属不变。

## 不混淆代码与实测

- 去掉第二个聊天模型可消除一段串行的 HTTP 聊天推理，但降低多少毫秒、云端费用变化及真实打断体验必须同网络/设备/Persona 做现场 A/B；单测不能证明 600–800ms 等绝对数字。
- 麦克风采集的 50Hz 回调仍在自身组件处理且每 10 帧更新一次帧计数；正式 Room/TTS 的 20ms PCM 节奏保持不变，不能为减少 React 渲染而丢音频帧。
- 保留双方原有未提交的 React 布局、配置和工作台修改；不把这些并行修改混入本轮后端 Commit。项目唯一主线和保留能力以当前 `PROJECT_RULES.md` 为准。
