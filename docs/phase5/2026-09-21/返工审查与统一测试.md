# Phase 5 返工审查与统一测试

供独立审查人员使用。代码闭环、Provider 真模型质量、Room 真人声学、设备实播是四种不同证据；不以自动化通过冒充体验通过。

## 审查范围

| 审查点 | 核查内容 |
| --- | --- |
| 新旧 ASR 归属 | realtime.py：新 item 到来后淘汰尚未确认的前一 item；迟到的旧 delta/ambient/final 不抢占新轮，同一 item 重复起声不重复 Hold。 |
| 异步所有权 | 旧 LLM 任务在流式输入、收尾和异常后核对 turn_id/会话身份；旧轮结束不能清掉下一轮正在进行的麦克风候选。 |
| 本轮真正输入 | 本轮调度前冻结身份指令、历史、最新问题；工具二次流式请求也保留追加后的真实 messages，工作台诊断与当前会话一致。 |
| 上下文边界 | 以完整对话轮次裁剪；不再出现截掉某个 user 却留下该轮 assistant 的消息级二次截断；更正和否定不截半句。 |
| 已播/未播 | 确认插话取消时仅保留已确认的用户原话；未播助手文本不得注入上下文；本地取消或断线不虚构有效轮次。内存缓存与 SQLite 重建一致。 |
| Persona | 身份、事实、动作限制等共性规则统一，三套 Persona 仅改变表达；不凭存在提示词就判定真实多轮质量合格。 |

## 自动化复核

在 brainv2 根目录执行：

    .venv/bin/python -m pytest -q
    .venv/bin/ruff check apps packages tests
    npm --prefix web run build
    npm --prefix web test
    sidecars/tts_viseme/.venv311/bin/python -m unittest discover -s sidecars/tts_viseme -p 'test_online_budget.py'

需按最终输出报告真实项目数及失败情况。单元测试不启动生产 Room，也不向真实机器人发送测试 PCM。

## 真模型现场用例

在同模型、同 Persona、同网络、同麦克风条件下，每组至少连续运行三次。每轮查 ASR item_id / transcript.done / last_llm_input 最后一个 user / text.delta 的 turn_id / Ledger / 扬声器回执。

| 操作 | 预期 |
| --- | --- |
| “我喜欢茶” → “不对，我说咖啡” → “刚才更正的是哪个？” | 最新事实是咖啡；旧茶的迟到 final 不能再触发回答。 |
| “讲个故事” → 回答时打断问“窗外有没有下雨？” | 新轮不继续旧故事；没有天气/视觉证据时不能假装已经查询。 |
| “明天去看电影” → “继续刚才的” → “你答应我什么了？” | 只接续真实上下文；没有说过的承诺不编造。 |
| “今天累，不想讲原因” → “别再问我了” → “知道了” | 不反复续问、不强迫继续聊。 |
| 长历史后切 Persona、Chat、机器人、重连 | 更正和否定留在所属会话；不同机器人事实不混用，首字延迟有实际样本。 |

失败样本记录时间、机器人/Chat/Persona revision、模型版本、匿名 item_id、turn_id、ASR final、last_llm_input、生成文本、Ledger status/播放回执及首字延迟。禁止保存密钥或传播私人对话。

若实际模型输入正确而回复旧话题，归为模型/指令/上下文语义问题；若最后一个 user 是旧问题，归为轮次输入问题；若文字正确而扬声器发旧音，归为 TTS/播放缓冲归属问题。

## 不可伪称已完成的边界

- Provider 没有 item_id 时不能凭本地时钟猜真实归属，须以实际 Qwen wire 留证。
- 播放设备只有采样游标、缺逐字可靠对齐时，无法保证模型知道用户听见了哪半句话；宁可不注入未经证明已播的文本，也不能捏造承诺。
- 真人声学、AEC、设备起停播、ForcedAligner 实际音素时间、真实模型多轮自然度和长时间恢复仍需要独立现场验收。
