# Phase 8C 软件验收核对｜2026-09-24

## 软件交付及证据口径

- 独立规划模型：`qwen3.8-max-0902`，只用于按需8C。项目配置的百炼 API 在现场实际请求返回合法结构化 `SPEAK/new_value`，未携带聊天内容、未发布 Room 音频；这**不是**真机闭环证据。
- Runtime 每机器人独立按最新用户回合和 robot/chat/persona/session_epoch/generation 管理候选。至少60秒空闲、已连接视觉文字 Room、最近10秒内同一人物 subject ID 连续至少2帧且相隔至少1秒、置信度≥0.8、恰好一人，才启动异步Graph。画面说明不能假装人物存在；其他机器人的事实不得借用。
- 模型返回 NO_SPEAK、报错或超时都结束这一段静默，不热路径重试。第一句经 Realtime 的现有 `source=external` 流程进入TTS；提交仅是`submitted_unknown`，不宣称扬声器播放。
- 二次追问须第一句同轮真实扬声器started + drained回执、播完后120秒、持续单人新鲜存在、新公共场景证据和模型`new_value=true`；最多二句，同义/重复话题拒绝。浏览器试听不能代替真机回执。
- 用户插话、Chat或Persona切换、视觉过期、Realtime离线、播放或事件繁忙均抑制；独立Graph及Qwen失败不能拦普通实时对话。
- 私有空间许可：仅在明确启用 `ANNIE_IDLE_TRUSTED_ROOM=1` 且TTS和API key具备时才可启用。**该开关不是身份验证。** 现有Realtime保留原会话历史；无法保证陌生人在场时绝不复述私人内容。公共场所及未经明确授权的旁人现场必须关闭8C，直到提供可信的人物身份/私密上下文隔离协议。

## 2026-10-08｜8C 软件核查与修复（现场仍待验）

- **人物稳定性修复：** 旧版未校验人的 `subject.id`，缺失ID也可累计两次。旧版把首帧后的等待时间算成两帧间隔，连续快速两帧+停顿1秒也可能触发。现在明确要求非空、长度受限的同一追踪ID，以及最近有效帧与首帧真实接收时间跨度≥1秒、两帧以上；人物置信度需处于0.8～1.0。此前不合格的现场消息保持静默。
- **二次证据修复：** 场景变化后不能凭单帧更新就再次提问；需要同一新公共场景有至少2次有效观察且跨越1秒，再同时通过真实扬声器started/drained、播完120秒、`new_value=true`与非重复话题。更严格的静默是有意的安全降级。
- **提交竞态修复：** `submit_text`在途时若用户开始说话，不允许迟到的成功结果把已抑制的轮次重新登记成可二次追问状态。后续用户回合由原Realtime/打断链自己管理；不能据此宣称扬声器已经停止。
- **外部工具硬约束：** 此前外部回合虽已拒绝动作、提醒及记忆工具，但`get_weather`仍有代码分支；现在同时拒绝，确保8C/8A外部发声不会沿旧用户的城市文本调用天气接口。真实用户主动查询天气不受影响。
- 软件代码及回归覆盖：`apps/runtime/src/annie_runtime/idle.py`、`realtime.py`、`tests/test_phase8c_idle.py`及`tests/test_phase8_events.py`。本次全量Python **322 passed、30 subtests、2条第三方弃用告警**；Ruff、uv锁、Git diff检查通过，前端类型检查及**37项前端测试**通过。未重新构建带未提交大屏改动的`web/dist`，也未启动/干预用户当前Room；这些自动化结果不包括物理持续视觉、真人语义、声学起停、设备回执可信性及真实隐私边界。**不自动开启 `ANNIE_IDLE_ENABLED`，不声称Phase 8整体验收通过。**
