# 具身智能大屏｜首轮实施与真实证据边界

## 当前交付

- **前端最终收束：只有一个 `web/` React/Vite 构建项目，两个正式视图。** `/?view=workbench` 是交互工作台，`/?view=cockpit` 是实时数据大屏（默认页）；生产由同一个 Python `web/dist/` 静态服务提供。已删除未引用的旧 `web/src/cockpit/`（原演示大屏）、重复 CDN 视频接收组件与过时浏览器测试。语音 sidecar `static/index.html` 仍是 sidecar 服务的算法验证界面及其测试依赖，属于现有 sidecar 功能资源，并非第三个正式前端，暂不删除。
- 大屏与工作台采用 React `lazy` 按需加载，不再一次装入两套视图；Three.js 限制约 24FPS，优先让 LiveKit 原生 `<video>` 解码与呈现。无网络模型时先展示本地程序化机械概念半身（明确非真机外观），有外部授权 GLB 则加载替换。
- 在既有 React 入口的 `cockpit` 视图替换为 `web/src/exhibit/`，保留原研发工作台。
- 真实只读 `GET /api/exhibit/robots/{robot_id}/snapshot`：读取 Realtime、Room、动作请求、输入计数、Phase 9 进程采样；未测量的数值返回 `null`。不消费旧大屏中固定的健康、注意力、声能指标。
- 按用户确认的内网部署直接访问：不要求两组令牌、登录、HTTPS 或逐次访客授权；旧环境中的展厅令牌不再改变访问结果。现有同源请求校验、机器人隔离及视觉新鲜度判断保留。
- 当前轮次文本与新鲜视觉语义直接显示；记忆召回、设备姿态等未接入数据仍显示未知，不借本次访问调整新增业务能力。
- 浏览器用真实授权的 LiveKit token 原生接视频；缺少服务配置或没有收到帧时显示待连接，不使用摄像头假图；URL、API Key、Secret、房间及 source 均来自部署配置，不猜机器人 Room 对应 LiveKit 房间。
- 中央 Three.js 数字孪生响应已下发动作指令做视觉预演；未收到设备回执就不显示物理执行成功。
- 原 `/api/dashboard/snapshot`、`/api/robots/{id}/cockpit`、`/api/dashboard/config`、`/ws/dashboard` 使用固定的健康分、负载及注意力分数，已删除并以只读 `/api/exhibit/` 替代，防止旧客户端错误展示伪指标。

## 展厅部署

1. 不需要初始化展厅访问凭据；旧凭据初始化脚本不是启动或访问前置。
2. 执行既有启动器后，内网浏览器直接访问 `http://<主机内网IP>:8780/?view=cockpit`，不需要登录与访客授权操作。
3. 真实视频配置 `.env` 中 `ANNIE_EXHIBIT_LIVEKIT_URL`、API_KEY、API_SECRET、SOURCE 和每个 robot 的 LIVEKIT_ROOM。支持 `ws://` 内网地址与 `wss://`；LiveKit 服务自己的订阅 token 仍由后端签发，服务密钥不发到浏览器。
4. 视频 token 45 秒有效；浏览器只接收所选机器人房间的指定 source 视频，切换机器人或离页释放连接。缺配置/无真实首帧时如实显示未配置或待连接。
5. `/models/annie-robot.glb` 可选覆盖临时概念机器人。没有本地模型时尝试锁定来源的 CC0 示例；若外网不可达展示本机 Three.js 程序化机械半身，不冒充真机。
6. 在项目根目录执行 `npm --prefix web ci && npm --prefix web run build`，然后 `bash start.sh`（Windows 为 `start.bat`），浏览器访问 `http://127.0.0.1:8780/?view=cockpit` 或 `?view=workbench`。独立电视与局域网浏览器可直接用主机内网 IP 的 HTTP 地址访问。
