# Persona / Chat 记忆与实体激活（本机软件改造）

## 本次范围与界面解释

- `robot_id` 是实体机器人/Room 运行边界；每个机器人只有一条激活的 `persona_id + chat_id`。Room 单路 PCM、网页文字、回复和执行证据走同一活动 Session。激活复用现有切换/取消、generation 隔离和 Realtime 重建，不把聊天历史复制到 Room。
- `persona_id` 是稳定角色 ID；`display_name` 是可修改的展示名称，**不是**客户 user_id；`style_id` 是该 Chat 的表达风格。四种 `annie*` 是**风格预设**，旧数据库中相同字符串的 `persona_id` 仍按旧角色保留，不自动并入 `annie`。
- 当前仍按 `robot_id` 隔离资源。工作台暂无客户登录、已验证 `user_id` 与授权关系，不能据前端文本做跨机器人/跨客户 Persona 搬迁。本次可将当前机器人列表中任一 Chat 一键激活到**当前选中的机器人**；跨机器人转移需身份/授权方案，不显示已支持。
- 同一机器人同一 Persona 各 Chat 共享既有长期 `semantic/persona/episodes`；`semantic` 仍是该机器人公共偏好。结构化 `chat_memories` 只属于对应 Persona+Chat，允许手动指定绝对到期毫秒值，默认持续到该 Chat 删除或明确遗忘。旧聊天 Ledger 独立保留，不因遗忘长期记忆被删除。
- 后台 LangMem 最多两条候选；一轮明确的“你不能骂我”等临时约束保守归入 Chat，除非用户明确长期要求。非必需的能力询问不应写入长期。旧误分类和重复长期条目**不自动迁移、不自动删除**；UI 需要由用户核对并更正。
- Realtime 建立连接时从本地 SQLite 有界载入当前 Chat 约束及少量长期事实；不增加聊天每轮云端检索，仍只在询问旧事时用 `recall_memory`。手动修改后若当前 Session 已建立，下一次重建/切换才会重新注入，近期已说出的原话仍在当轮上下文中。
- `expires_at_ms` 为手动明确的绝对有效期；含“下周”等无锚点的自动抽取仅作为 Chat 暂存，不能推断客户所在地时间、自动生成提醒或当成永久将来事实。真实有效期/时区仍需用户可验证的事件时间。

## 数据迁移与不做事项

- schema v7 仅新增 `chat_memories`、`conversation_chats` 和本机 `persona_instances`；迁移回填既有角色与有历史的 Chat，保留已有长期向量、记录 ID、版本、原文和所有聊天回合；即使新 Chat 尚无发言也能重新激活。
- 不自造认证客户 ID、数据库跨机器人共享、声纹身份推断或真机执行成功回执；不暗改 Phase 7/8 已交付的 Room 与 Graph 合同。

## 验收

- 自动化：`tests/test_persona_chat_memory.py` 覆盖旧库升级、Persona/Chat 隔离、短期约束、到期、删除、空 Chat、激活/风格以及旧 generation 请求拒绝；现有 Phase 3/5/6/7 回归不得倒退。
- 工作台人工：同 Persona 创建两个 Chat，Chat 1 写入“今天不要骂我”，Chat 2 不出现该约束；两 Chat 仍共享该 Persona 旧长期事实；激活 Chat 1 后，观察 Robot 对应 Room 与 Realtime generation 变化，实际 PCM/扬声器仍待真机签收。

## 抽取质量与记忆筛选补丁

- 工作台记忆面板新增“公共长期 / 角色专属 / 当前 Chat”三个真实筛选；角色专属含关系与经历，公共仍只在**此机器人**共享。新角色不因选用同一说话风格而自动继承另一角色经历。
- 自动抽取返回 `no-extractable-content` 等空结果解释时在入库前拒绝，不生成向量；实际无事实应由模型返回空列表。对用户单句“我喜欢你”只记录客观的“曾向当前 Persona 表达喜欢”，不能推断永久好感。
- 自动抽取只在**同作用范围**内做保守的完全同文去重，以及“我喜欢你”已存在的历史异名检测，阻止新写；包含已遗忘的匹配行，避免换 key 重新复活。不对任意语义接近文本使用激进模糊合并，以防把“喜欢/不喜欢”“过去/现在”等不同事实合并。
- **既有**重复行、手动确认行及截图中的错误 `no-extractable-content` 行均不擅自删除；用户可在对应记忆面板逐条遗忘/更正。此补丁仅阻止新坏记录进入库，避免违背“遗忘仅删除长期记忆，聊天原文保留”。
- 旧版无效空结果保留供用户查看与遗忘，但标注“历史无效项”，不计入有效数、模型启动记忆或检索证据；因其 key 无效，不提供直接更正文案，应遗忘后用新的事实键手动添加真正的记忆。
