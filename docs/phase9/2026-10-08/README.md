# Phase 9｜性能与诊断完善

## 软件范围与当前结论

- 正式Runtime只增加每进程一个2秒异步采样器（CPU进程用量、事件循环调度延迟、Unix系统峰值RSS），不轮询PCM、不新增数据库表/服务/Trace写入；API复用`/health`和已有Realtime诊断接口。Windows峰值RSS当前未提供，必须返回`null`而不是虚构数值。
- 最近128个Realtime回合保留有界时间点、状态和音频/文本/外部分类；分段优先用本机单调时钟计算；旧本机接收wall-clock时间点回退标识`local_wall_fallback`。缺少speaker回执标未知。分位数同时报告样本数及缺失数，取消/失败/未结束独立计数，不能用成功样本P95冒充完整服务可靠性。
- Developer抽屉关闭时不触发额外诊断轮询；打开期间5秒轮询一次当前进程健康，显示资源/Trace队列/ledger积压，并在已有分轮视图查看源与统计。无独立性能前端；不修改用户并行未提交的大屏。
- 不改现有动作、提示词、模型、TTS、ForcedAligner、Room合同；**本阶段不做双头嘴型。**

## 合成压测与证据边界

- 自动化：`uv run --locked pytest -q tests/test_phase9_performance.py`（有界128轮、原始证据、错误/取消、CPU探针启停/健康）及原有阶段回归。
- 手工合成压测：`uv run --locked python tests/phase9_pressure.py --turns 10000 --robots 2`。2026-10-08本机结果：10,000个本地模拟回合、双机器人，写入耗时约87.99ms，记录事件每轮P50 0.0083ms / P95 0.0103ms，128轮上界。该测量只包含内存中的事件写入，不含真实ASR、网络、模型、TTS、SQLite、设备执行或UI，不是端到端首响承诺。精确数值随硬件与负载变化，需复跑。
- 同机100,000轮额外回放：946.48ms，每轮事件写入P50 0.0088ms、P95 0.0111ms；依然是软件模拟而非端到端基线。本轮 Python全量 **326 passed**、前端 **37 passed**、TypeScript/Ruff/uv锁/diff检查通过；未修改或清理并行未提交的大屏文件。
- 回归测试和可复跑压力脚本保留在`tests/`，正式代码不导入它们。所有阶段完成并验收后，可按用户确认清理一次性性能脚本、临时HTML和冗余测试副本；**不在Phase 9期间清空tests/**。
