# 演示问题修复：不该看画面却去看、一句话的方言被带到后面、被打断后重答旧问题（2026-11-25）

11-25 19:30–19:35 演示（annie-a / roomv2，温柔性格，main 分支；日志 `var/logs/runtime-20261125-181253.log`，对话在 `var/runtime.db`）暴露的问题。三处都能在日志和库里对上，下面分开写。

```text
本次问题与范围：演示里三段对话的异常（见第 1 节）；只改主脑对话链（look 决策、打断后的上下文、一句话方言的作用范围）。
目标与用户可见效果：
  ① 不需要看画面的话（“向面前的人介绍一下你自己”）不再被“先看再答”压住回复、多等 1.6 秒；
  ② 一句话的方言/外语要求只管那一句，下一句闲话回到原来的说法和声音；
  ③ 她被打断后，下一句不再先把上一个没说完的问题再答一遍。
输入 → 处理 → 输出：
  ① 识别终稿 → 决策模型判“要不要看”（问题里写明介绍自己、对面前的人说话不用看）；d3 置信度 <0.6 当作不看 → 提前回复照常放行；
  ② 识别终稿 → 模型调 select_reply_style → 一句话的要求在这句回复结束时一并清掉 → 下一句按默认；
  ③ 播放中被打断 → 删掉没播完的助手条目，并在原位插一条“被打断”标记 → 下一句只答新问题。
改动文件：apps/runtime/src/annie_runtime/{realtime,language,__init__,__main__}.py、
  packages/annie-brain/src/annie_brain/decision_policy.py、config/runtime_defaults.toml、
  tests/{test_vision_look_decision,test_phase4_realtime,test_reply_language,test_loose_instructions}.py。
保留项：d3 判“要看”≥门槛时的先看再答流程不变；阿里决策模型（d3 不在线时的回退）的判定不变；
  “这个会话/以后都用 X”“用 X 话跟我聊天”这类持续要求仍然一直有效；模型凭证据推断出的方言仍然延续；
  未播助手条目照旧整条删除（不冒充已说）。
不做事项：不改提示词、不换模型、不碰 ASR（识别乱码）、不改 TTS/嘴型/网页；不为“只答应一句就停”另加补答兜底。
结果：自动化通过；真机/真人声待验（见第 5 节）。
```

## 1. 现象

| 时间 | 用户（识别文字） | 小安妮 | 问题 |
| --- | --- | --- | --- |
| 19:32:22 | 你能用四川话向面前的人介绍一下你自己吗？ | 要得嘛，我这就用四川话给大家介绍一下自己。 | 只答应了一句，没有介绍；气泡带“👁 看了画面” |
| 19:33:13 | 透明优势感，肯定说话，肯定从魅力。 | 好嘞，我这就用陕西话夸夸你。……嫽得很…… | 识别文字是乱的（模型直接听音频，听懂了“陕西话夸夸”）；下一句闲话（19:33:32“这个算法是说我们自己训练的”）也带着“咧” |
| 19:34:03 | 你能用俄语介绍一下今天天气怎么样吗？ | Sure! Beijing is the capital of China……（英文）+ 俄语天气 | 先说了一段没人问的英文北京介绍，才答俄语天气 |

## 2. 原因

### 2.1 不该看画面却去看（第一行）

- 日志 19:32:22.495：`vision_intent_decision … judge=d3 choice=front confidence=0.5413 …`，随后 `vision_intent … vision_wait_ms=1564`，`turn_latency … tool_calls=0 reply_chars=21`。回复刚好 21 字，就是那一句应声。
- `_look_decided` 对 d3 的“要看”没有任何置信度门槛，0.54 也照做：压住提前回复、等视觉描述 1.6 秒、再让模型重答。这句话根本不需要看画面；工作台因此出现“看了画面”。
- 日志里 d3 一共判过 14 次“要看”：置信度 <0.6 的 2 次（0.43“你忘记眼前的人”、0.54 本次）都是误判，≥0.6 的 12 次都是真要看（最低 0.60“饮水机在哪里呢”）。11-25 d3 实测（dev-next 分支 `docs/开发记录/2026-11-25/d3决策模型实测与新场景.md`）：置信度 <0.6 时“要不要看”准确率约 88%，≥0.8 为 99.5% 以上，建议 ≥0.6 采信。
- 阿里决策模型（d3 不在线时回退）不一样：日志里它判“要看”的 24 次里 17 次低于 0.6，其中“你看这边”（0.33）、“看我这儿”（0.57）、“小安妮小安妮看我”（0.35）等多是真要看。它的置信度不可靠，所以**不设门槛**。
- 没查清的部分：模型为什么在这条先看再答的路径上只说了应声就停。用同样的提示词和 11-25 当天的历史，用文字输入真实模型（qwen-audio-3.1-realtime-plus）：没有“刚看到的画面”提示 6 次、有提示 4 次（另 2 次遇到额度报错），都给出完整介绍；把被丢弃的提前回复里的 `select_reply_style` 调用留成“悬空”再追问（flash，精简提示词）3 次也都给出完整介绍。所以这次“只应声”没能复现，现在的修复是让这句话不再走那条路径。

### 2.2 一句话的方言被带到后面（第二行及其后）

- 19:32:53 “你能用陕西话夸一夸我吗？”：模型调用 `select_reply_style(zh, shaanxi)`，记入 `ReplyLanguageState.intent`。`intent` 只在 `reset()`（被打断、换会话）、用户说“别说 X 了”或空闲 180 秒（需语种旁路喂观测）时才清，回复结束只去掉情绪。
- 结果这句“只管一回”的要求（10-22 用户决定：带着具体内容的只管这一回，下一句回到原来的说法）变成了会话级：下一句 `selection()` 仍是陕西话，TTS 音色和提示词里的“目标语种”都是陕西话。确定性复现：一句要求走工具后，下一句无关闲话的 `selection()` 仍返回 `shaanxi`。
- 19:33:13 的识别乱码不是代码问题：阿里实时模型自带的转写把用户的话写成了乱字，模型直接听音频听懂了。本次不动。

### 2.3 被打断后重答旧问题（第三行）

- 19:33:47 的英文北京介绍 317 字（约 20 秒语音），19:34:03.59 俄语问题的终稿到达时还没播完（该轮 `playback_evidence_status=unknown`，已播文本为空）。
- 打断时 `_interrupt_active_turn` 把没播完的助手条目整条删掉（Qwen 只支持删条目，不能按播放位置截断），但用户那条音频还留在提供方上下文里。于是提供方看到“英文北京介绍的问题，没有答案”。俄语这轮先调 `get_weather`，工具后的续答发生在删除之后：先把没答案的旧问题再答一遍（220 字英文），再答新问题（115 字俄语天气）。`reply_chars=337` 正好是两段加一个空行。
- 凡是“播放中被打断”，提供方上下文里都会留下一条没有答案的用户消息；之后的续答（工具、先看再答）更容易把它再答一遍。不是只有这一次。

## 3. 改了什么

| 位置 | 改动 |
| --- | --- |
| `decision_policy.py` `_LOOK_CRITERIA["none"]` | “不用看”的说明加上“让她介绍自己、对面前的人说话、打招呼或表演”，交给决策模型判断，不加句式规则（用户 11-25：介绍自己才是重点，死规则别再加） |
| `decision_policy.py` `HELD_REPEAT_QUESTION` + `realtime.py` `_held_repeat` / `_judge_held_repeat` / `_ignore_utterance` | 压住的提前回复和她前面某句回答（含没收到播完回执的）相似度 ≥0.6 时，问决策模型（d3 在线用 d3，否则阿里）：要她再说（照放）/ 新的话（撤回重答）/ 不是对她说的（不回：丢弃这一轮，删掉这句音频，记作旁听）；没有决策模型时保持原规则（≥0.85 且不是“再说一遍”才撤回重答） |
| `realtime.py` `_look_decided` | d3 的“要看”要求置信度是数字且 ≥ `d3_min_confidence`（默认 0.6）才算；`vision.intent.decided` 事件和 `vision_intent_decision` 日志新增 `accepted`；阿里回退判定行为不变；门槛 0 = 不设 |
| `config/runtime_defaults.toml` `[vision.intent.decision]` | 新增 `d3_min_confidence = 0.6`（含依据）；`HarborRuntime` 校验 0～1，非数字/布尔拒绝；启动日志 `vision_look_decision_config` 和 `/health` 里可见 |
| `language.py` `reply_intent` / `response_finished` | 模型经工具选的语言/方言，如果正是用户这句“只管这一回”的要求，就在这句回复结束时清掉；“这个会话/以后/用 X 话跟我聊天”等持续要求、凭证据推断的方言照旧延续 |
| `realtime.py` `_delete_unheard_items(interrupted=True)` | 打断（`_interrupt_active_turn`）和本地取消（`cancel`）删没播完的助手条目时，先在它后面插一条助手消息“【这条回答被用户打断，没说完】”（`previous_item_id` 指向它），再删它；标记用 `【】` 包着，万一模型照念会被舞台旁白过滤掉 |
| `realtime.py` 错误处理 | 提供方对“找不到 previous item”的报错（`Cannot find previous item with id: X`，`invalid_value`）只在我们刚请求过标记时当作已忽略，其余报错照旧断线重连 |

拒绝/先看再答/保留的提前回复等其它 `_delete_unheard_items` 调用点不加标记：那些是要把同一句话重新答一遍的场合。

提供方接口（QwenCloud 文档 + 实测）：`conversation.item.create` 支持 `previous_item_id` 把条目插到指定条目之后；锚点不存在时返回 `{"type":"invalid_request_error","code":"invalid_value","message":"Cannot find previous item with id: a1","param":"conversation.item.create"}`（先建标记再删条目，锚点在）；锚点存在的建标记请求在实测里没有报错。

## 5. 没验证的和遗留

- **标记对真实模型的效果没量到**：演示里的重答只在 plus 上出现过一次，flash 复现不了基线；现在能证明的是接口接受、报错被豁免、顺序正确（单测），以及原因链（日志+库）。plus 额度恢复后可用 11-25 的原话（英文北京介绍 → 播放中问俄语天气）做前后对比。
- **plus 额度**：探针结束时 `qwen-audio-3.1-realtime-plus` 返回 `Allocated quota exceeded, please increase your quota limit.`，`3.1-realtime-flash` 正常。不确定是演示和探针一起用完的还是原本就快没了；需要在百炼控制台看额度，或像 11-20 那样用 `.env` 的 `ANNIE_REALTIME_MODEL` 临时换 flash（换模型要用户定）。
- **“只应声就停”的真正原因没查到**：现在的修复是不再让这句话走先看再答；如果在正常路径上再出现，下一步是（a）`USER_REQUESTS` 里把“简短答应”限定为“只是切换方式的要求”，带内容的要求要直接说出内容；或（b）补答兜底（一句话的语言要求 + 回复短且是“我这就…”时由主脑补一次）。两者都改变对话行为，等实测后由用户决定。
- 第二行的**识别乱码**（阿里实时模型自带转写对方言口音/多人场景）这次没动；这类句子里“用 X 话”不会被规则识别，只能靠模型听音频自己判断。
- 阿里回退判定在 d3 不在线时误判“要看”的情况（如 11-05“我一开始跟你说我今天穿的什么颜色的衣服”0.51）这次没处理，原因见 2.1。
- 真机/真人声待验：四川话/陕西话/俄语的实际发音、被打断后下一句的内容。

## 6. 用户反馈后的补充（同日）

- **“介绍自己是重点”、死规则别再加**：去掉了先加的“介绍自己”句式规则，改为在决策模型的“要不要看”问题里写明“让她介绍自己、对面前的人说话、打招呼或表演”不用看。阿里决策模型回放：改前“向面前的人介绍一下你自己。”判 front 0.53；改后 3 句自我介绍都判 none（0.74/0.60/0.56），4 句真要看的（面前有什么、穿什么颜色、水桶在哪里等）不变。d3 当时 404，没测。
- **旁人无目的的话（用户选方案 1，用决策模型、先阿里后 d3）**：现在不会自动忽略这类话的原因：用户 10-30 关了对话对象判断（`ANNIE_ADDRESSEE_ENABLED=0`，本次仍关着），smart_turn_v2 主要判断这句话说完没有、是不是环境音，不判断是不是在对她提要求；她准备的回复只和上一句回答相似 0.69（第二段 0.79），原防复读要 0.85；而且上一句没收到播完回执，原来根本不在比对范围里。
  - 纯规则试算（回复像上一句、这句和上一句没共同的词等）在历史里约一半误伤真要求（“我叫海城”“看我这儿”），没用。
  - 现在：压住的回复和她前面某句回答相似度 ≥0.6 就问决策模型三选一（见第 3 节）。问法写成“麦克风刚收到一句话”：写成“用户这句话”时，阿里把三句旁人的话判成 new/again；改写后 6 句回放全对——“透明优势感…”0.62、“他的脖子不动了…”0.71、“这个柜子就是3楼的…”0.92 判 not_for_her，“我叫海城”判 new，“看我这儿”“再夸我一次呗”判 again。
  - 只影响“她要把前面的回答再说一遍”的少数句子，其它句子不多问一次模型；决策模型出错/不在时照旧回答。
