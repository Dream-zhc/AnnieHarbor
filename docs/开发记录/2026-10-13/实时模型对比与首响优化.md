# 实时模型对比与首响优化

> 2026-10-13。用户要求试用 `qwen-audio-3.1-realtime-plus`，测试自行完成、待决事项自行决策，并补齐日志。本文记录改动、真实云端实测、决策与遗留项；不是设备/声学验收。

## 结论

- **默认 Realtime 模型改为 `qwen-audio-3.1-realtime-plus`。** 语音链路首响与 3.0-flash 持平（大模型在云端判定“说完”的约 0.8 秒内已开始生成），上下文使用、慢工具前导语和讲解质量更好。回退只需把 `config/providers.toml` 的 `[realtime].model` 改回 `qwen-audio-3.0-realtime-flash`，或设 `ANNIE_REALTIME_MODEL`。
- **接入改用业务空间专属域名**（官方推荐；本地 `.env` 的 `ANNIE_REALTIME_URL` / `ANNIE_TTS_URL`，不写入代码或 TOML）。
- 实测“人声结束 → 首段音频发往 Room”P50 约 1.2～1.4 秒，其中**云端 smart_turn 判定说完约 0.76～0.79 秒是最大头**，其次是 TTS（首个带标点分句到首包约 0.4 秒）。连接复用每轮约省 50ms，属于小收益。
- 修复两个无唤醒模式下的真实 Bug：模型在识别终稿前发起的工具调用被直接拒绝；以及上一轮 TTS 回合残留时，新一句“先调工具”的回复被当作打断而取消（语音设提醒 4/4 失败 → 修复后 4/4 成功）。

## 代码与配置改动

| 范围 | 改动 |
| --- | --- |
| 模型选择 | `annie_adapters.realtime` 增加同协议族模型校验；`HarborRuntime(realtime_model=)`、`[realtime].model`、`ANNIE_REALTIME_MODEL`；健康快照新增 `model`、`endpoint_host` |
| 当前时间 | Session 指令注入北京时间（分钟级，用户开始说话/提交文字时刷新）；记忆开场时间改为北京时间 |
| TTS 连接 | 按官方建议跨任务复用 WebSocket；用户开口/提交文字/打断后预热；空闲超过 25 秒或复用时未收到 task-started（1.5 秒）即换新连接，未提交任何文本，不丢字 |
| 记忆开场 | 预算 512 → 1024 字节，长期事实 3 → 6 条 |
| 天气 | 未说城市时使用 `providers.toml` 默认城市并说明；当轮须是天气询问；允许调用前先说半句 |
| 提示词 | 新增独立“语音输出”段：首句短、不用列表/Markdown、没听清请对方重说；人格风格文本未改。长度规则与性格已在[提示词精简与性格重写](提示词精简与性格重写.md)中修订 |
| 早到工具调用 | 识别终稿前的工具调用暂存（绑定所属音频条目），终稿确认后按该回合校验执行，无效/环境音则逐个回拒绝结果且不再续说 |
| 打断 | 打断只取消已有回合归属的 response，不再取消正在确认的新一句回复 |
| 续推理 | 回复已开口且动作/表情已受理时不再追加第二轮生成 |
| 日志 | `realtime_ready`、`turn_latency`、`tts_latency`、`speaker_latency`、`tool_call`、`tool_followup`、`tts_prewarm`、`tts_reuse_failed`；只记数字/ID，不记对话内容 |

新增长期回归 `tests/test_realtime_model_latency.py`（10 例）；`test_tts_mixed_mode`、`test_tts_expression_regressions`、`test_tts_failure_recovery` 中“每轮新建连接”的假设改为复用后的预期。

## 实测方法与证据级别

- 一次性探针在 `var/tmp/20261013-realtime-ab/`（结束后已删除）。真实 DashScope 业务空间域名 + 真实 `HarborRuntime`；Room 发布用内存捕获替身，**不经 Room、无设备回执**；天气用高德格式的固定数据。
- 语音输入用同一 TTS 音色合成 6 句用户话，soxr 24k→16k，按 20ms 实时推流，句后持续静音；“人声结束”取最后一个 RMS>300 的帧，与运行时单调时钟同源。
- 样本量小（文字 16 轮/模型、语音 10～12 轮/模型），只用于比较与定位，不是 P95 达标证据。
- 最后一次 `sh start.sh` 实测使用了真实 `.env`：本机可连到 `192.168.1.47` 的 Room，一条文字测试回复（“现在是晚上七点零九分。”）被发到 roomv2 并收到扬声器起播回执。该实例运行约 2 分钟（为缺失的本机模型临时关闭唤醒词/嘴型/云端 AEC），日志确认期间无语音回合、无工具和动作。

## 决策记录

| 事项 | 决定 | 理由 |
| --- | --- | --- |
| 默认模型 | 3.1-plus | 语音首响持平、更聪明；文字输入慢约 150ms、话多已用字数上限压缩。单价更高，需在百炼控制台核对 |
| 接入域名 | 专属域名 | 官方推荐，实测不慢、TTS 尾延迟更稳 |
| 唤醒期间提前合成 TTS | 不做 | 业界默认也等确认；被拒时白合成 |
| 表情动作改正文标签 | 不做 | 违反“动作经 Function Calling”硬规则；仅记为建议 |
| 设置类工具合并 | 不做 | 官方建议工具清晰区分 |
| 联网搜索 | 不做 | 内置搜索与 tools 互斥，另接需新增模型调用 |
| 人格风格文本 | 不改 | 用户撰写的内容；问题见下 |

## 遗留与建议

1. **smart_turn 判定说完约 0.8 秒**是最大头，`threshold/silence_duration_ms` 对它不生效。改 server_vad（静音 400～500ms）可能更快，但会失去语义判停、`turn_invalid` 和环境音过滤，需真人测试后再定。
2. 带表情动作或工具的回合首字多 0.6～1 秒（先调工具再说话）。只有改为正文内联标签才能消除，需用户先改规则。
3. 保留的 65 条回复中“这点倒挺有意思”出现 6 次、“我倒觉得”8 次，另有一次出现在失眠倾诉的开头（3.1-plus 首轮文字测试）。自然陪伴风格的惯用语示例被模型过度模仿，已在[提示词精简与性格重写](提示词精简与性格重写.md)中处理，最终实测降为 0 次。
4. 探针无扬声器回执，按设计上一轮回复被视为“未听到”并在新一句打断时从云端上下文删除，导致工具回合后模型重复回答上一题。这是测试条件造成的，真机需核对 drained 回执是否及时。
5. `tests/test_acoustic_sidecar.py` 两个 1 秒计时用例在基线和本次改动下各 20 次均偶发 2 次失败，属原有不稳定。
6. 本次在聊天中出现了 DashScope 与高德密钥，建议在控制台轮换。
