# 视觉意图：先看再答（2026-10-28）

用户要求：监听动作回执，同步视觉意图事件，等视觉描述，给模型最新的画面。用户有视觉意图（“你看看左边有什么”“你看看周围”“你看到了什么”“你瞅瞅我拿的什么”）时，有匹配动作就先等嵌入式 `action.finished`，再拿视觉帧、出描述、再让模型回答和放行 TTS；没有匹配动作就直接拿最新画面。有视觉意图用阿里云模型，没有就照常用本地视觉。后续补充：先定义发到 `reb_main` 的视觉意图字段，由字段决定走阿里云还是本地模型，说明交给视觉会话对接；视觉端模型不用主脑这边调研；动作立即触发不加新字段，用 `offset_ms=-1`。

```text
本次问题与范围：问左边/上面有什么时转头要等她开口才执行，描述的是转头前的画面。定义主脑↔视觉端的 vision.intent 字段与嵌入式立即触发约定，实现主脑侧。
目标与用户可见效果：有看向动作时她先转头，转到位后才回答且答的是转过去看到的；“你看到了什么”“我拿的什么”先请视觉端看最新一帧再答；普通对话不变。
输入 → 处理 → 输出：识别终稿 → 规则判断视觉意图 → 作废云端抢答 → action_trigger(offset_ms=-1) → action.finished → reb_main vision.intent(route) → vision.intent.result → 新画面写入会话指令 → response.create → TTS。
拟改文件：decision_policy.py、actions.py、realtime.py、vision_intent.py（新）、__init__.py、__main__.py、runtime_defaults.toml、.env.example 与测试；规范两份。
保留项：10-27 看向规则、一轮一个动作、回执按 conversation_id+script_id 匹配、唤醒/追问准入、插话打断语义、每秒一条的本地画面。
不做事项：视觉端实现与云端模型选型（视觉会话负责）、嵌入式改动、网页改动、环顾动作。
未决业务/协议/硬件问题：look_* 回 action.finished 时头是否停在该方向；新动作撞上正在执行的动作时嵌入式怎么处理；视觉端需新增订阅 reb_main。
结果：软件回归通过；开关由用户提交 727cac6 改为默认打开；晚间实测发现打字问法没走先看再答，已修（见文末）；真机待验。
```

## 1. 字段（交给视觉会话与嵌入式）

- [视觉意图协议](../../规范/视觉意图协议.md)：主脑 → 视觉端 `vision.intent`（`intent_id`、`conversation_id`、`route=cloud|local`、`question`、`fresh_frame`、`after_action`、`deadline_ms`），视觉端 → 主脑 `vision.intent.result`（`status`、实际 `route`/`model`、`description`、`frame_after_request_ms`、`latency_ms`、`error`）；两条都走本 Room 的 `reb_main`，按 `intent_id` 对应。视觉端不用自己等嵌入式回执。
- [动作立即触发](../../规范/动作立即触发.md)：`action_trigger` 的 `offset_ms=-1` 表示立即执行、不等音频（用户确认的嵌入式约定，不新增字段）。

## 2. 主脑怎么做

| 步骤 | 做法 |
| --- | --- |
| 判断视觉意图 | `decision_policy.asks_to_look`：看/瞅/瞧 + 周围、四周、眼前、左右上面等；“你看到了什么”“能看到我吗”；“我拿的什么”“我手里是什么”“我穿的什么”；“瞧瞧这是啥”；10-27 的看向说法和“转头看看”。“我看看”“让我看看”“你看这事怎么办”“附近有什么好吃的”“别看了”等不算 |
| 压住这一轮 | 识别终稿时判断；云端在终稿前抢先生成的回复（唤醒/追问窗口里本来就先暂存）直接作废并删掉，迟到的云端回复也取消；这一轮的文字和 TTS 都不出 |
| 先转头 | 有已启用的 `look_left/right/up` 就立即 `action_trigger(offset_ms=-1)`；倾听动作还占着电机时最多重试 1.2 秒 |
| 等回执 | 等同 `conversation_id + script_id` 的 `action.finished` / `action.dropped`，最多“动作时长 + 1.2 秒”，超时记 `timeout` 也照常往下走 |
| 请视觉端看 | 发 `vision.intent`：有动作 `fresh_frame=true` 并带 `after_action`；没有动作立即发、`fresh_frame=false`；`route` 取配置 |
| 回答 | 收到 `ok` 就把描述作为“刚为用户这一问看到的画面（转向左边后刚拍的…）”写进会话指令（不是用户发言），确认后才 `response.create`；描述在指令里留 30 秒供追问。失败或超时就按每秒一条的本地画面照常回答 |
| 被打断 | 等待期间用户又说了有效的话，按原插话规则作废这一问，迟到的回执和描述都丢弃 |
| smart_turn 丢掉的话 | 补判补答的那句如果是视觉问题，同样先看，再按文字补问 |

动作只做一次：这一轮的“点名动作”路径不会再转第二次头。

## 3. `offset_ms=-1` 的影响范围

主脑自己掐时机、调用 `perform_now` 发出的动作全部改为 `offset_ms=-1`：视觉意图的转头、用户说话时的倾听动作、她说每句话时配的动作、说完后的内心反应。以前它们都发 `0`，如果嵌入式按 `0` 等这一轮音频，倾听（这一轮还没有她的语音）和说完后的反应（语音已播完）可能等不到。随回复开口的点名动作、模型调用的动作和表情仍发 `0`。

## 4. 开关与配置

`config/runtime_defaults.toml` 的 `[vision.intent]`：`enabled`（最初默认 `false`，用户 10-28 18:43 提交 727cac6 改为 `true`）、`route`（默认 `cloud`）、`deadline_ms`（默认 3500）、`action_receipt_extra_ms`（默认 1200）；`.env` 的 `ANNIE_VISION_INTENT_ENABLED=1/0` 覆盖开关。只对有摄像头画面（订阅了 `visualllm`）且开了 TTS 的机器人生效，目前是 A（`roomv2`）。开着而视觉端还没实现 `vision.intent` 时，每个视觉问题要多等约 3.8 秒，再按本地画面回答。

诊断：工作台事件 `vision.intent.started/result/abandoned/look_skipped/reply_held`；运行日志每问一行 `vision_intent robot=… turn=… script=… receipt=… action_wait_ms=… status=… route=… model=… vision_wait_ms=… vision_latency_ms=… total_ms=…`；`/health` 的 `vision_intent.configured_robots`。

## 10-28 晚实测：打字问的没有先看（已修）

用户在工作台打字问了 5 句（18:38–18:41：你看看左边有什么、你看看右边有什么、你看看左右有什么、那你看看周围呢、你看看左边；日志在 `docs/运行日志/2026-10-28/`），都是立刻回答，转头随回复发出、`offset_ms=0`，18:38 那句答成“暂时看不清左边的东西呢。”。

- **原因**：先看再答只接在语音的识别终稿上。工作台打字走 `submit_text`，写入用户文字后直接 `response.create`：模型调 `look_closely` 按旧画面答；转头走 10-27 的点名动作路径，等她第一帧语音才发、`offset_ms=0`。日志里这几轮都是 `turn_started … input=text … cause=submit`，没有一行 `vision_intent`。
- **修复**：打字的视觉问题同样先看再答：写入用户文字后不立即 `response.create`，转头（`-1`）→ 等回执 → `vision.intent` → 描述 → 再回答。启动日志新增一行 `vision_intent_config robots=… route=… deadline_ms=… tts=…`：导出的日志里没有 `/health`，以前看不出一次运行有没有打开、哪个机器人挂上了（打开开关的 727cac6 提交于 18:43，晚于 18:38 的这次运行）。
- **新增测试 3 项**：打字问左边先转头（`offset_ms=-1`）、回执和描述到了才 `response.create`、只转一次；普通打字照常立即回答；她还在说话时用语音问右边，同样先转头、抢答不出声。
- **回归**：`uv run --locked pytest -q` 1278 passed / 1 skipped；`npm --prefix web test` 132 通过；ruff 与 `uv lock --check` 通过；隔离根 `sh start.sh` 真实拉起，工作台 200、`/health` 503（Room 故意不可达），启动日志有 `vision_intent_config`。
- **待验**：语音和打字各问一次“看看左边有什么”，看日志 `vision_intent robot=…` 那一行（`receipt`、`status`、`total_ms`）和启动时的 `vision_intent_config robots=annie-a … tts=True`。18:38 那次 `look_left` 一直没有回执（`published_unknown`），同期其它 41 个动作里 39 个有 `device_finished`，需要嵌入式看一下；没有回执时主脑最多多等“动作时长 + 1.2 秒”。
