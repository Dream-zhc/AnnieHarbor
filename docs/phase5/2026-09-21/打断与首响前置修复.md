# Phase 5 前置：旧回复归属、服务端未播历史与短句首响

## 实际修改

- 本地取消先标记旧 `response_id`，再发 `response.cancel`，并在接收端拒绝旧 ID 的文本、工具与 `response.done`；旧回合不得结束新回合。缺失 ID 的事件不能伪称可精确归属。
- Qwen `response.cancel` 会保留已生成文本。跟踪该响应的助手 `output_item` ID，服务端响应取消后请求 `conversation.item.delete`；若模型已结束但独立 TTS 尚未获真正扬声器 `drained`，本地打断也请求删除对应助手项。完整真实扬声器 `drained` 后不再删除。仅发出删除请求不等于收到服务端确认；无 ID 时发 `context.unheard_unverified`，不能声称已净化。
- Qwen 不提供等价于 OpenAI `conversation.item.truncate` 的精确播放游标截断：部分播出的整个助手项从服务端上下文排除；不编造已说的半句。实际 PCM→字词边界和删除确认仍待现场验证。
- TTS 首段等待达到配置上限后，允许已积累的至少两个有效字符直接提交，避免短句在 `response.done` 前长期静默；不把一个孤立字自动当完整语句。

## 审查报告中不能当作实测的推断

- `CONTEXT_CHAR_BUDGET=12000` 为字符代理，不是固定 1.5万–2万 Token；降低到 2000 字符不保证 TTFT 150ms，并可能抹掉最多 20 轮的重要更正与承诺。本轮保留已有的有界完整轮次策略，真实预算优化须以 P50/P95、模型 token 用量及质量反例为据。
- `_restore_context()` 的逐条 `socket.send()` 不是逐条等待服务端 RTT；不能直接宣称 40 次发送等于 40 次网络往返。
- 多协程共享缓存的竞态须定位具体跨 `await` / 线程交界；单事件循环内的同步字典操作不因“没有锁”就自动脏写。不能加一把全局锁挡住多机器人。
- 不进行通用问号/反问句硬裁剪，否则会删掉必要澄清及问句中的事实；不凭空给“茶→咖啡”错误附会 30% 概率。

## 验证与未完成证据

- 已增加旧 `response.done` 与新回合交错、Qwen cancel 后助手项删除、完整播放后不删除、TTS 短句等待上限的自动化回归。
- 现场仍需验证：真 Qwen 删除确认，响应无 ID 或服务端输出 ID 缺失时如何降级；设备报告的真实进度与采样游标，真实 ASR、AEC、首文本/TTS/扬声器的 P50/P95，三套 Persona 多轮质量。Mock/发送请求不替代这些证据。
