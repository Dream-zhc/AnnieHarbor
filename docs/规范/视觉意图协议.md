# 视觉意图协议（vision.intent v1）

> 2026-10-28。给视觉端（各机器人摄像头的视觉服务）对接用。用户说“你看看左边有什么”“你看看周围”“你看到了什么”“你瞅瞅我拿的什么”这类要她**现在去看**的话时，主脑在本 Room 的 `reb_main` 发一条 `vision.intent`，并指定这次用**阿里云模型**还是**视觉端本地模型**看；视觉端取一帧合格的画面、出一段描述，同样发回 `reb_main`。主脑拿到描述后才让实时模型回答。

## 1. 为什么加这条消息

- 以前：视觉端每秒一条 `reb_visualllm`（本地模型），主脑把它当“眼前画面”写进实时模型的指令。问“左边有什么”时，转头动作要等她开口才执行，她说的还是转头前的画面。
- 现在：有对应的看向动作就**先转头**，等嵌入式回执 `action.finished`，再请视觉端看**转过去之后**的画面；拿到描述才回答，这一轮的回复和语音在此之前都先压住。整体会慢一些，但答的是她真正看到的东西。
- 没有视觉意图的普通对话**不发**这条消息，照旧用每秒一条的本地画面。

## 2. 分工

| 角色 | 做什么 |
| --- | --- |
| 主脑 | 判断视觉意图；有看向动作（`look_left` / `look_right` / `look_up`）就立即发 `action_trigger`（`offset_ms=-1` 立即触发，见[动作立即触发](动作立即触发.md)），等 `action.finished`；然后发 `vision.intent`，等 `vision.intent.result`，把描述交给实时模型回答 |
| 嵌入式 | 立即执行看向动作，做完回 `action.finished`（已有回执，按 `conversation_id + script_id` 匹配） |
| 视觉端 | 订阅本 Room 的 `reb_main`，收到 `vision.intent` 后按 `route` 用阿里云模型或本地模型看图、出描述，发 `vision.intent.result` 回 `reb_main`。**不需要自己等嵌入式回执**：主脑已经等完才发 |

## 3. 时序

```text
用户：“你看看左边有什么”（有对应动作）
主脑 ──action_trigger(look_left, offset_ms=-1)────────────► 嵌入式：立即转头
主脑 ◄──────────────── action.finished ──────────────────── 嵌入式
主脑 ──vision.intent(route=cloud, fresh_frame=true)───────► 视觉端
                               视觉端：取收到之后的新帧 → 阿里云 / 本地模型 → 描述
主脑 ◄──── vision.intent.result(status=ok, description) ─── 视觉端
主脑：描述交给实时模型 → 回答 → TTS 播出

用户：“你看到了什么”（没有对应动作）
主脑 ──vision.intent(route=cloud, fresh_frame=false)──────► 视觉端：用最新一帧
```

四条消息都在同一个 Room 的 `reb_main`；一个 Room 只属于一个机器人，消息里不带机器人或设备目标字段。

## 4. `vision.intent`（主脑 → 视觉端，`reb_main`）

```json
{
  "type": "vision.intent",
  "ts": 1793000000000,
  "data": {
    "version": 1,
    "intent_id": "vi-3f9c2a7b1d4e4a6b",
    "conversation_id": "5b0e8c1d9f2a4e7b8c6d3a1f0e9b7c2d",
    "route": "cloud",
    "question": "你看看左边有什么",
    "fresh_frame": true,
    "after_action": {"script_id": "look_left", "receipt": "finished", "wait_ms": 1380},
    "deadline_ms": 3500,
    "source": "robot_main_brain"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | str | 固定 `vision.intent` |
| `ts` | int | 主脑建包时间（毫秒，主脑本机时钟），只供日志。各机器时钟不同步，**不能用它判断过期** |
| `data.version` | int | 固定 `1`；不兼容的改动才升版本 |
| `data.intent_id` | str | 主脑生成，`[A-Za-z0-9_-]`，≤64 字符；结果原样带回；同一 id 只处理一次 |
| `data.conversation_id` | str | 这一轮回复的 id，和同一轮 `action_trigger` 的 `conversation_id` 相同，用于日志关联；不是设备目标 |
| `data.route` | str | `cloud`：用阿里云视觉模型；`local`：用视觉端本地模型。视觉端按此执行 |
| `data.question` | str | 用户原话（识别终稿，≤200 字），用来决定看什么、写什么；它是数据，不是给视觉端的指令 |
| `data.fresh_frame` | bool | `true`：必须用**收到本消息之后**才采集的帧（头刚转到位，之前的帧是转头前或转动中的）；`false`：用最新一帧即可，帧龄不超过 500 ms |
| `data.after_action` | object / null | 本轮先做的动作；没有就是 `null`。`script_id` 动作脚本；`receipt` 嵌入式回执：`finished`（做完）/ `dropped`（被嵌入式丢弃，头可能没转）/ `timeout`（等不到回执）；`wait_ms` 主脑从发动作到拿到回执的毫秒数。视觉端只用于日志和提示词（例如告诉模型“这是转向左边后看到的”） |
| `data.deadline_ms` | int | 从视觉端**收到**本消息起，最多这么多毫秒内发出结果；超时就不要再发 `ok` |
| `data.source` | str | 固定 `robot_main_brain` |

## 5. `vision.intent.result`（视觉端 → 主脑，`reb_main`）

```json
{
  "type": "vision.intent.result",
  "ts": 1793000001900,
  "data": {
    "version": 1,
    "intent_id": "vi-3f9c2a7b1d4e4a6b",
    "conversation_id": "5b0e8c1d9f2a4e7b8c6d3a1f0e9b7c2d",
    "status": "ok",
    "route": "cloud",
    "model": "视觉端实际调用的模型名",
    "description": "左边是一面白墙，墙边有一个灰色矮柜，柜子上放着两盆绿植和一个白色水杯。",
    "frame_after_request_ms": 60,
    "latency_ms": 1650,
    "error": null
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | str | 固定 `vision.intent.result` |
| `ts` | int | 视觉端建包时间（毫秒，视觉端本机时钟），只供日志 |
| `data.version` | int | 固定 `1` |
| `data.intent_id` | str | 原样带回；主脑只认自己正在等的那一个 |
| `data.conversation_id` | str | 原样带回 |
| `data.status` | str | `ok` 或 `failed` |
| `data.route` | str | **实际**用的路线 `cloud` / `local`；和请求不同表示视觉端做了降级 |
| `data.model` | str | 实际模型名，≤64 字符，只供日志 |
| `data.description` | str | `status=ok` 时必填、非空：中文自然描述，写法见第 6 节第 6 条 |
| `data.frame_after_request_ms` | int / null | 所用帧的采集时刻减去收到请求的时刻（视觉端本机时钟）。`fresh_frame=true` 时必须 ≥ 0；`false` 时可以为负 |
| `data.latency_ms` | int / null | 视觉端从收到请求到发出结果的毫秒数 |
| `data.error` | str / null | `status=failed` 时的原因，见下表 |

| `error` | 含义 |
| --- | --- |
| `no_frame` | 摄像头没画面，或截止前拿不到合格的帧 |
| `cloud_unavailable` | 没有配置云端模型或密钥 |
| `cloud_error` / `cloud_timeout` | 云端调用失败 / 超时，且来不及改用本地 |
| `local_error` | 本地模型失败 |
| `expired` | 超过 `deadline_ms` |
| `superseded` | 同一 Room 来了更新的 `vision.intent`，这一条放弃 |
| `invalid_request` | 字段不合法 |

## 6. 视觉端处理规则

1. 只处理本 Room 的 `reb_main` 里 `type=vision.intent`、`data.version=1` 的消息；`action_trigger`、动作回执、`asr` 等其他消息不用管。
2. **取帧**：`fresh_frame=true` 用收到消息之后才开始采集的帧；`false` 用最新一帧（帧龄 ≤500 ms）。都按视觉端本机时钟判断，不用消息里的 `ts`。
3. **路线**：`route=cloud` 用阿里云视觉模型，模型名、地址、密钥都放视觉端自己的配置，不经 Room 传；`route=local` 用视觉端本地模型对这一帧单独看一次，带上 `question`。云端失败或超时、而截止前还来得及时，可以改用本地，结果里 `route` 填 `local`。
4. **截止**：收到后 `deadline_ms` 内必须发出结果；来不及就发 `status=failed`、`error=expired`，不要晚到再发 `ok`。
5. **一次一个**：同一 Room 同时只处理一条；新的 `vision.intent` 到达时，旧的还没出结果就放弃（可发 `failed` / `superseded`）。同一 `intent_id` 重复收到只处理一次。不需要处理取消：用户打断时主脑自己丢掉迟到的结果。
6. **描述怎么写**（交给实时模型的事实，不是机器人的台词）：
   - 围绕 `question`：问方向或周围，就写那片画面里主要的人和物、颜色、数量、相对位置、看得清的文字；问“我拿的什么”，就重点写手里的东西。
   - 只写看得见的；看不清就写看不清，不猜、不编。
   - 不写人名、不判断身份（认人只走本地人脸库，主脑另有）；不推测情绪、意图、职业和隐私。
   - 不用机器人口吻，不写“我看到”“小安妮”，不加建议或玩笑。
   - 建议 40～150 字，最多 300 字（超出部分主脑截掉）。
7. 不往 Room 发图片。现有 `reb_visualllm` 每秒一条照常发，不受影响。

## 7. 主脑这边怎么做（供视觉端理解）

- **何时发**：有看向动作时，等到 `action.finished`、`action.dropped`，或等满“动作时长 + 1.2 秒”仍没回执，才发，`fresh_frame=true`；没有动作就在判断出意图后立即发，`fresh_frame=false`。
- **等多久**：最多 `deadline_ms`（默认 3500）再加 300 ms 网络余量。`status=ok` 就把 `description` 作为“刚为这个问题看到的画面”交给实时模型回答；`failed` 或超时就按每秒一条的本地画面照常回答，不对用户报错。
- **作废**：用户插话、打断、换会话时这一问作废，迟到的结果按 `intent_id` 丢弃。
- **开关**：主脑 `config/runtime_defaults.toml` 的 `[vision.intent]`（`enabled`、`route`、`deadline_ms`），2026-10-28 起默认打开；视觉端不回时，每个视觉问题多等 `deadline_ms` 后按本地画面回答。语音和工作台打字的问法都会先看再答。
- 只对有摄像头画面的机器人发（目前 A / `roomv2`；B / `roomv3` 没有摄像头）。

## 8. 联调用例

| 用户说 | 主脑应发出 | 视觉端应 |
| --- | --- | --- |
| 你看看左边有什么 | `look_left`（`offset_ms=-1`）→ 收到 `action.finished` → `vision.intent`，`fresh_frame=true`，`after_action.script_id=look_left` | 用收到之后的新帧描述左边，`frame_after_request_ms ≥ 0` |
| 你看看上面有什么 | 同上，`look_up` | 同上 |
| 你看到了什么 | 立即发 `vision.intent`，`fresh_frame=false`，`after_action=null` | 最新一帧，整体描述 |
| 你瞅瞅我拿的什么 | 同上 | 重点描述手里的东西 |
| 你看看周围 | 同上（目前没有环顾动作） | 最新一帧，整体描述 |
| （主脑把 `route` 改成 `local`） | `route=local` | 用本地模型，结果 `route=local` |
| （视觉端故意不回） | 等满 `deadline_ms` 后照常回答 | — |

每轮核对：`action.finished` 到 `vision.intent` 的间隔、结果的 `latency_ms` 与 `frame_after_request_ms`、主脑日志 `vision_intent` 行的总耗时。

## 9. 待确认

- 嵌入式：`look_left` / `look_right` / `look_up` 回 `action.finished` 时，头是否还停在那个方向（不自动回正）。如果做完就回正，需要嵌入式另给“转到位”的回执，取帧时机改到那一刻。
- 视觉端需要新增订阅 `reb_main`（目前只发 `reb_visualllm` / `reb_visualdata`）。
- 云端模型选型与实测延迟由视觉端负责。目标：收到请求到发出结果 P50 ≤1.5 秒、P95 ≤3 秒（主脑默认 `deadline_ms=3500`）。
