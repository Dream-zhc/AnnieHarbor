# 板端杂音、交互变慢与阿里连接失败

> 2026-10-21 晚。用户反馈：大头新板子扬声器有杂音；唤醒、说话延迟不对劲，实时交互变差；项目有时和阿里建立连接失败。日志在 `docs/运行日志/2026-10-21/日志/logs/runtime-20261021-17*.log`（17:26～17:41 Brain 启动了 5 次）。开发基于最新 main（含 PR #7 和另一位开发者 16:13～18:07 的板端脚本与 d3 决策路由提交）。

## 修复

- **阿里与 Room 一律直连**：新增 `annie_adapters/net.py`。Realtime、TTS、旁听识别三条 WebSocket 默认 `proxy=None`；需要时设 `ANNIE_CLOUD_PROXY`（如 `http://127.0.0.1:7890`）才走代理。Room 的监听、推送、PCM 输入三处也明确直连（局域网）。qwen-flash 对话对象判断（httpx）也不再读系统代理。
  - 本机同样设了 3 个代理环境变量，改后实测：连接类型为直连 `ClientConnection`，Realtime 握手 70/50/51 ms，TTS 59/52/56 ms。
- **删除不存在的记录不再断线**：记下我们请求删除的条目，服务端回“Cannot find item with id: X”且 X 是 30 秒内我们刚要删的，视为已删，不重连；其它同类错误照旧。
- **188 扬声器**：板端软件音量设为 80（≈ -3.9 dB，抵消 DOV 的 +3.9 dB 硬件增益，整体回到 0 dB），已重启服务，日志“音量 80”。板端说明已补注意事项。如嫌轻，说“音量调到90/100”即可恢复；若杂音不变，说明是硬件底噪，需要换声卡或检查供电。

## 验证

- `tests/test_cloud_link_1021.py`（5 项）：默认直连、设环境变量才走代理、Room 永远直连；Realtime/TTS/旁听识别三处连接都传了代理选项；删除未找到只在我们刚请求过时忽略。
- 完整回归：后端 1079 passed, 1 skipped；ruff、锁文件通过；网页 121/121。
- 未实测：Brain 那台机器换上本版后的连接稳定性与延迟；188 音量 80 后是否还有杂音（需要现场听）；TTS 账号问题需用户在控制台处理。
