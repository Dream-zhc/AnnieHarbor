# 云端唤醒与交互准入（2026-10-08）

## 已接线（代码回归，不等于设备验收）

- 单 Runtime 使用一份可选的 `livekit-wakeword` ONNX 推理实例；每个 robot 独有 PCM 环形缓存、状态、超时与计数。
- 每路 Room PCM 保留原有 16kHz/16bit/mono 契约；休眠 PCM 只送云端唤醒检测，不送 Qwen Realtime。Wake 成功后继续复用现有 smart_turn 和 TTS HOLD/Resume。
- 状态：`SLEEP` → `WAKE_WAIT`（5s）→ `ACTIVE`（最长30s无播放回执的保护窗口）→ `FOLLOWUP`（扬声器 `drained` **真实**回执后8s）→ `SLEEP`。在 `FOLLOWUP` 期间检测到 Qwen speech_started 可重新进入 `ACTIVE`。
- 唤醒检测用最近2秒音频，每0.5秒最多判一次；命中时回送结尾240ms缓存（12个20ms/640字节帧）以降低紧邻首句的截断风险。该缓存无法精确定位唤醒词结束，是否导致多余回复仍待设备验证。
- 不再把 `ambient_audio_transcription.completed` 按文本猜测升级为用户回合，避免环境聊天直接引发本地 `response.create`、Chat写入、动作。
- 未配置模型时唤醒功能默认关闭，旧热路径不变；显式开启但模型缺失/推理包未安装时报错，不静默退回持续上送。

## 启用条件

1. 在**独立训练环境**按官方 VoxCPM 中文路径运行 `config/唤醒词训练.yaml`，导出 `xiaoannie.onnx` 并离线评测。需单独安装对应训练依赖；生产 Runtime 不安装训练依赖。
2. 将通过评测的模型存入本机 `var/models/xiaoannie.onnx`（不提交权重），在 Runtime 虚拟环境安装可选推理包 `livekit-wakeword==0.3.0`。
3. 将 `.env.example` 中的 `ANNIE_WAKEWORD_ENABLED=1`、`ANNIE_WAKEWORD_MODEL=var/models/xiaoannie.onnx` 及阈值加入私有 `.env`；从 React 工作台测试两个机器人各自 Room。

## 尚未完成／不能声称已解决

- **中文唤醒模型未训练、未评测。** 合成中文训练数据不足以代替真人近音词、方言、真实房间、噪声、远场与回声验证；阈值 `0.5` 只是初始参数。
- **不是说话人身份识别。** 单路混合 PCM 不能证明哪个人在说话；8秒 FOLLOWUP 内旁人插话仍可能被 smart_turn 接受。严格解决必须新增声源/身份可信证据，不能仅靠正则文本。
- **缺少真实音频端到端证据。** 需验证连续唤醒与首句同气息、仅喊小安妮不误答、两机器人双路并发的误唤醒/漏唤醒/CPU/P95、真实 speaker `drained`、重连、超时和打断。
- 唤醒模型读取的2秒 PCM 含麦克风环境声，短期缓存只在内存且不持久化。休眠时不向 Qwen 发送 PCM，但实时 WebSocket 仍保持连接（沿用项目原本的15分钟闲置回收机制）。

参考：`https://github.com/livekit/livekit-wakeword` 官方 README 的中文 VoxCPM 训练和 ONNX 推理指南。
