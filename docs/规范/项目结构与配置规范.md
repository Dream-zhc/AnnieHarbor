# 项目结构与配置规范

本文件是 Annie Harbor 的目录地图；硬约束以根目录`PROJECT_RULES.md`为准。

## 目录唯一职责

```text
brainv2/
├── apps/runtime/          # 唯一Python进程bootstrap、RobotRuntime/Realtime Session生命周期与TurnCoordinator
├── packages/              # 主工程可复用Python包
│   ├── annie-core/        # 纯核心类型/状态，不依赖框架和Provider SDK
│   ├── annie-brain/       # 对话策略、按需LangGraph复杂任务/后台LangMem；当前仅Fake Brain
│   ├── annie-adapters/    # SQLite及Realtime/TTS/Room/ForcedAligner等真实协议/SDK边界
│   ├── annie-observability/
│   └── annie-web/         # FastAPI接口边界，不是第二套前端
├── web/                   # 唯一前端工程；Phase 4原位升级React/TypeScript工作台
├── config/                # 可提交的非敏感TOML配置
├── sidecars/              # 只有确需独立进程的算法能力
├── tests/                 # 主工程自动化验收
│   └── test_phase*.py     # 长期自动化回归；临时HTML已删除
├── docs/                  # 规划、架构、规范、阶段记录和历史证据
└── var/                   # SQLite、日志、缓存、临时文件等本机运行数据
```

根目录只留工程入口与规则，不再放临时计划、日志、数据库或过程Markdown。

`resources/`、`third_party/`、`tools/`以及新的细分文档目录均为按需目录：只有第一个真实文件有当前职责时才创建，禁止用占位文件预建。

## 正式前端落位（Phase 4C完善基础，后续增量）

- `web/`已有React + TypeScript + Vite及npm锁文件，直接复用；Phase 4C负责把布局导航、组件样式、API/事件与状态边界、构建测试和Phase 1–4B已有功能接齐并验收。后续按同一结构增加真实功能，不另建frontend目录或第二套页面工程；基础完成条件见总计划第22.1节。
- Phase 4C动效统一GSAP + @gsap/react；精确版本基线、用途和验收以总计划第22.6节为准，实施时才改`web/package.json`及唯一npm锁文件。简单交互用CSS；不另建动画工程或引入多套引擎。
- `web/src/`承载会话、PCM、对话和开发者视图；`web/tests/`保留原回归覆盖并补充组件/接线测试。模块随实际功能创建，不预建后续空目录。
- 正式运行由Python提供`web/dist/`构建产物，开发热更新服务只用于开发；同步调整现有构建/静态资源入口，不能仍发布未构建的React源码或静默展示旧页面。
- 复用Phase 2/3既有协议与会话API，正式后端接口仍在`packages/annie-web/`，业务规则仍由Runtime负责；浏览器不持有Provider密钥。构建与加载验证、已有功能迁移和恢复步骤属于Phase 4C整合交付。
- 具体页面目标与验收仍以总计划为准。`tests/html/`临时入口及挂载已按用户确认清理；后续用户统一测试仅使用现有React工作台，不新增第二套前端。

## Realtime职责边界（规划，尚未接线）

普通PCM对话不调用LangGraph；Audio Input Gate、Event Router、Speak Policy、TurnCoordinator按真实需要在既有包内最小落位，不新增空壳包。annie-core仅持有纯类型/规则，不引SDK/Graph；LangGraph/LangMem仍仅在annie-brain，Graph只为复杂任务启用。

Realtime输出文本，独立Qwen-Audio-3.0-TTS-Flash输出PCM，ForcedAligner用同一PCM与文本对齐再映射嘴型。简单动作/表情/工具经Function Calling校验执行；复杂任务结果经SpeakRequest回Realtime表达。Persona按Session/revision加载，不逐轮灌完整Prompt。

## Room与六通道归属（本期固定）

一个robot绑定且独占一个Room；Room内main/tts/mic/visualdata/vision/sam是同一机器人的六个通道，不是六个业务房间。每Room的mic只输入一路连续PCM，A/roomv2与B/roomv3分别隔离；本期不实现同房间多机器人、多输入混流或新增设备target协议。

`config/robots.toml`保留robot→room绑定；`config/rooms.toml`保留完整六通道地址/映射。只启用mic不授权删除其它五通道；后续阶段逐步接线而非反复删建配置。配置结构迁移、删除资产、Room语义变化先问用户，未接入能力不提前标ready。

## 配置放置

`config/app.toml`保存服务默认参数；`config/robots.toml`保存机器人实例定义；`config/providers.toml`保存当前确认要继续接入的LLM/TTS、本地视觉、天气等非敏感Provider默认值；`config/rooms.toml`保存Java Room各房间地址；`config/runtime_defaults.toml`保存V2后续阶段仍会使用的业务默认值；`config/action_scripts.json`和`config/attention_scoring.json`保留仍有效的动作/注意力业务合同。Persona配置在Phase 3出现真实Persona schema与数据时再创建目录。长期记忆配置只在Phase 6真实接入时按LangMem/Store实际需要新增。

V1 的 `skills.json` 不迁入 V2：它混合能力目录、关键词触发、Prompt 注入、旧路由和设置页开关，属于旧架构耦合。后续每项能力在真实接入阶段按最小契约重建。

这些迁移配置在对应阶段接线前只是**配置资产**，不能因为文件存在就把Room、Realtime、LLM、TTS或视觉标记为已连接。Realtime目标模型/音频规格/工具目录只在Phase 4真实接入时更新；现有Provider值不在规划任务中切换。LangGraph checkpoint只在Phase 8真实工作流出现时创建，不作为聊天持久化前置。

敏感信息和机器本地差异固定放根目录`.env`，模板为`.env.example`。当前bootstrap使用标准库自动读取`.env`，不引入`python-dotenv`。环境优先级为：CLI > 系统环境 > `.env` > TOML。

当前支持的本地覆盖：

```text
ANNIE_HOST
ANNIE_PORT
ANNIE_DATABASE
ANNIE_LOG_LEVEL
```

`.env`永不提交。真实API Key等未来也只进入`.env`或部署系统提供的环境变量。

## 环境与依赖

Python固定3.11；`.python-version`声明版本，`uv.lock`锁定解析结果，`.venv/`是唯一主工程虚拟环境。不要把系统Python、Conda环境或父仓库venv当成运行依赖。

主工程新增依赖只改`pyproject.toml`并更新`uv.lock`。sidecar自己的requirements只服务sidecar，不能反向污染主Runtime。

## 运行数据

所有可再生产物统一写`var/`；数据库路径规范化并解析符号链接后仍须处于根`var/`内。该校验已进入长期回归。当前约定：

```text
var/runtime.db       # Runtime SQLite，当前schema v2
var/pytest/          # pytest cache
var/ruff/            # ruff cache
var/uv-cache/        # start脚本使用的uv cache
var/tmp/             # 启动临时文件；一次性复核使用其下任务唯一子目录
```

后续日志建议`var/logs/`，forensic建议`var/forensic/`；只有实际功能落地时创建，不提前制造空目录。

## 启动约定

macOS/Linux运行`./start.sh`，Windows运行`start.bat`。两者最终必须进入同一个`python -m annie_runtime`。

替换前先完成不破坏旧实例/数据库的配置、静态资源与数据库可访问性/格式/schema版本预检；失败时旧实例继续服务。该预检顺序已进入长期回归。

默认端口8780。`start.sh`/`start.bat`会传入`--replace-existing`：若目标端口的`/health`能够明确证明现有服务是Annie Harbor，则先对该服务返回的PID发送终止信号、等待listener释放，再启动新实例。若端口由其他服务占用或身份无法确认，则退出非0，**不得按端口盲杀**。禁止静默随机换端口。

直接执行`uv run --locked python -m annie_runtime`时仍保持保守语义，不主动替换已有实例；自动替换只由统一启动脚本显式开启，方便调试时避免意外终止进程。

`.zshrc`、PowerShell profile等属于用户Shell环境，项目启动不得依赖它们。

## 性能边界

实时主链只保留业务必要步骤。配置启动时读取一次；高频Trace批写；队列有界；网络调用显式timeout/cancel；不同机器人实例无全局回合锁。未经profile证明，不加缓存层、进程池、Redis、复杂事件总线或额外服务。

## 测试与复核文件保留

长期Python回归在`tests/`、前端回归在`web/tests/`；现有协议fixtures保留原归档。历史`tests/html/`、相应挂载和临时压测脚本已删除。项目规划开发完成后暂停Phase 10/11及后续阶段，由用户稍后统一实测，之后仅按Bug修复；不要删除整个`tests/`或重建阶段测试页面。

一次性审查/复核脚本、测试库、日志、复制测试树与回滚快照放`var/tmp/<任务唯一标识>/`。任务执行者在成功/失败清理钩子及结束前核对中释放自建资源并删除临时产物；有效复现先并入正式回归。未解决或并行任务在用的证据仅保留最小集合，注明责任任务与清理条件；不批量删除真实运行数据。详见`PROJECT_RULES.md`“验证脚本与测试产物生命周期”。
