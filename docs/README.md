# 文档入口与优先级

本文件用于限制AI和开发者的默认阅读范围，避免历史记录覆盖当前设计。

## 默认只读

1. `PROJECT_RULES.md`：最高优先级工程规则。
2. `docs/规划/小安妮V2后端开发总计划.md`：唯一阶段路线图与当前架构方向。
3. `docs/规范/项目结构与配置规范.md`：当前目录、配置和运行数据规则。
4. `AGENTS.md`：执行入口和当前阶段提醒。

## 按任务读取

- 外部协议、Room、小脑、设备、兼容性：读`docs/phase0/2026-09-17/`中的README、External Contract、协议清单、行为清单与fixtures。
- 核对已完成Phase 1骨架：读`docs/phase1/2026-09-17/README.md`。
- 其他任务不要默认递归扫描整个`docs/`。

## 文档保留规则

- 计划只保留总计划和当前阶段必要方案，阶段完成后删除重复的临时实施计划。
- 阶段目录只保留一个摘要README和仍有回归价值的合同/fixture；红绿日志、命令转储、完整源码快照、重复diff和已完成迁移审计默认删除。
- 当前代码、配置和自动化测试优先于历史阶段文字；历史阶段文档不得反向定义当前架构。
- 新的架构决策直接更新总计划/规范，不再保留已废弃实现的源码、配置或“兼容占位”。
- 不保留空目录、占位文件、中英文同义目录或仅供历史追溯但已无协议/回归价值的文件；目录在第一个真实文件落地时再创建。
- 每个实现阶段都必须有可视化验收HTML，统一放`tests/html/`；所有阶段完成并进入最终整合后直接删除整个`tests/html/`目录。
