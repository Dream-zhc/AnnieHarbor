# 语音延迟与模型诊断修正

## 主界面

- 撤下旧版“停声→ASR Final 2ms”“停声→首字 2ms”。其起止点仅是本地收到 Provider 事件的时间差，不是用户声学停声或纯 LLM 推理延迟。
- 主指标改为模型停声回调（本地收到）→ `source=speaker` 的扬声器起播回执（本地收到）。这仍是**设备自报口径，不是声学校准测量**；缺少任一端时间戳显示 `—`。
- 同一 Turn 的 TTS 首音频使用任务启动→收到首个音频字节的 `first_audio_ms`；首音频→Room 首帧来自两条后端事件。不同 Turn 绝不拼接计时。
- P50/P95 只取存在同轮 `speaker` 回执的样本；浏览器试听不能冒充设备回执。

## 开发者诊断

- 可选当前 Chat 的最近 20 轮及进行中的最新 Turn。`turn_id` 关联 Provider Session；最多保留当前运行期同一机器人/Chat/generation 的 4 份 Session 提示词快照、32 个 Turn 关联。进程重启后旧轮没有发送快照时显示“未留存”。
- 快照记录**实际发出的** `session.update.instructions`、工具名称、启动记忆/历史证据条数与原文，以及初始化时恢复的历史轮次。云端在 Session 内部追加/裁剪的真实完整上下文**不可见**，不得声称是逐轮完整 Prompt。
- 原文快照不进入常规 `/health`；仅在诊断抽屉打开时针对所选机器人按需调用 `/api/robots/{robot_id}/diagnostics`（5 秒、避免请求重叠），关闭后不轮询。此接口沿用当前 Runtime 的访问边界，正式多客户场景仍须引入身份鉴权。
- Function Calling 独立保存 64 条最近 `tool.called/tool.result`，不被高频 ASR 事件挤走；每个调用含 turn_id、call_id、原参数、真实返回、耗时。`recall_memory` 另显示实际返回证据条数；无记录不解释为证据绝对为零。
- 最近 Turn 分段耗时移入诊断，不再和主界面的端到端指标混为一谈。所有负时间差/缺少时间戳显示 `—`。

## 自动检查

`tests/test_phase4_realtime.py` 覆盖真实 `session.update` 快照一致性、独立工具追踪、记忆返回数、跨机器人隔离、上一轮停声时间戳不能复用以及回执来源；`web/tests/latency-diagnostics.test.mjs` 覆盖无回执/错 Turn/逆序时间戳时不能展示伪延迟。

物理验收仍需真实扬声器上报 `tts.playback.started`，并核对其报告点确实是 DAC/硬件播放开始；软件无法仅凭房间 PCM 发布证明已经出声。
