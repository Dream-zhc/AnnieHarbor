# V2 Phase 0 协议基线

日期：2026-09-17。

Phase 0协议资产整理已完成；真实wire、接收端寻址/播放回执、正式性能与模型质量基线仍待补证据，不表示真实联调验收全部完成。该目录现在只保留仍会影响后续兼容性和回归的协议资产，不再保存迁移过程日志、完整源码快照、旧Prompt快照或重复验证输出。

## 当前保留真源

1. `external_contract.json`：机器可读的外部协议合同。
2. `external_protocol_inventory.md`：Room、小脑、视觉、嵌入式、TTS/嘴型等协议说明与未决边界。
3. `behavior_inventory.md`：必须保持的关键行为语义。
4. `fixtures/`：协议、取消身份、多机器人、TTS出口和陪伴场景样例。
5. `action_catalog.json`：现有动作ID目录。
6. `latency_baseline.json`：V1历史延迟基线，只用于对比，不代表V2当前性能。

## 使用规则

- 只有处理外部协议、兼容性、Room通道、cancel身份、TTS/嘴型或回归时才读本目录。
- 当前架构、依赖和阶段顺序以`docs/规划/小安妮V2后端开发总计划.md`为准；Phase 0不得反向定义当前实现。
- fixtures中标注的synthetic/test数据不能冒充生产抓包。
- 历史资料中的同房间多设备target仍是未证明协议事实，但2026-09-18已确认当前V2产品采用“一机器人一Room”，因此它不再阻塞Phase 2输入Gateway。
- 多机器人长期记忆默认隔离；共享范围只允许显式配置。

## 仍需补证据的外部边界

- 小脑发送端、嵌入式接收端对cancel身份、输出和播放回执的真实处理。
- 真实原始WS packet与设备起播回执。
- 更大样本的P50/P95和陪伴体验对比。

这些缺口不影响Fake Runtime和纯内部阶段开发，但在真实多头输出联调和最终切换前必须解决。
