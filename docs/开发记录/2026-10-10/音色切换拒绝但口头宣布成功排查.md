# 音色切换拒绝但口头宣布成功：现场排查与修复

## 现场证据

- 2026-10-10 19:13:28，annie-a 当前 Chat 用户说「换一个音色。」；Realtime LLM 提交 `select_voice({"voice_name":"半藏森林","scope":"chat"})`。
- 当时 Runtime 将该调用拒绝，`tool.result.status=rejected`，原因 `voice name must appear in the current user turn`。之后 LLM 却说「现在音色换好了」，是不实宣告。
- 当时真实 `/api/robots/annie-a/voices` 为 `chat_voice_id=__default__`、`robot_voice_id=__default__`；SQLite `voice_preferences` 为零行。后续 TTS 快照实际使用默认音色。故非声音相似导致听辨困难，而是没有切换。

## 修复

- 明确指名：对比用户当轮文本和可用音色名；LLM 猜测的不同名字不授权切换。
- 不指名的「换一个音色」：若当前只有一个不同音色可选，直接选中该音色；若有多个候选，返回 `needs_selection`，要求先询问用户；重复选当前音色则为 `already_selected`，不是成功换声。
- 工具输出对 Realtime 显式给 `voice_changed=true/false`，没有成功绝不允许说已经换好；会话指令明确当前实际音色，成功后异步刷新指令。无需 LangGraph 或另外一次模型决策。
- 新一次 TTS `run-task` 才选择音色，延续已有音频、打断、ForcedAligner 时序；诊断记录 SHA-256 截断的 `voice_fingerprint`，不会记录完整私有音色 ID。按轮保留该值，和 `tool.result` 关联以确定实际提交的是哪条音频任务。
- 不主动修改现有真实用户音色偏好；现场 Runtime 未重启，待安排安全上线后由用户复测。
