# 对话气泡、天气及追问证据修复

## 现场复核

- `2026-10-09 17:45:29` 用户语音文本为「小爱你，北京今天天气。」；SQLite 内助手回复“天气数据暂时迷路”，但现场 Session 工具历史已被重置，无法倒推出这次是否实际调用 `get_weather`。当前 Session 的工具清单确实包含 `get_weather`。
- 用本机配置的高德 Key，通过现有 `AmapWeather.current("北京")` 复测：默认 1200ms 上限返回 `unavailable/timeout`；独立 3500ms 上限复测成功，实际 `fetch_ms=1200`，证明原限额偏紧，但**无法据此反推历史轮的确切错误**。
- `2026-10-09 17:48:26` 用户说「好累呀，想下班」，SQLite 只存一条 Realtime 回复。气泡来自 `reply-bubbles.ts` 按句号问号自动拆为最多三块，不是多轮模型回复。
- 同时现有 `external-events` 显示短时续聊：`qwen3.8-max-0902`、thinking 开启、9,331ms、`NO_SPEAK`；这个单独决策在原始 Realtime 回复完成之后，不是 17:48 回复内问句的来源。8C 环境主动交谈因视觉人物证据缺失被抑制。
- A 机器人当前人格 `annie-lively` 含「好家伙」「这局有意思了」固定范句，容易复读，与用户疲惫情境冲突。

## 变更范围

- 工作台仍一轮一条消息、一条持久化 Turn：移除按 `。！？` 拆气泡的展示逻辑；保留回复原有标点与段落、TTS 行为不变。
- 高德天气单次超时配置 1200ms → 2400ms，不添加同步重试；在原有提示下增加「失败不主动扯旧话题」。天气结果与拒绝原因沿原工具诊断查看；缺失历史工具事件标「未见证据」，不伪称成功或失败。
- 短时续聊和 8C 空闲规划分别保存每机器人、每 Session 最近 32 条独立规划结果（实际决策、源 Turn、结果 Turn、耗时、话题、失败/抑制原因），通过既有 `/diagnostics` 只读展示，并由前端按所选 Turn 筛选。无调用时不伪装评估成功。诊断是进程内有界证据，重启后不保留；不加入音频主链额外调用。
- 取消活泼性格写死的惯用语例句，疲惫时收住玩笑；保留既有四套风格及选择方式。

## 遗留边界

- Realtime 即时追问由主模型自行生成，**没有**独立模型逐条审核。只有短时续聊和 8C 空闲主动交谈的实际 `SPEAK/NO_SPEAK` 才是独立 LangGraph/Qwen 规划证据。
- 旧历史 Weather Function Calling / Idle Graph 调用不凭数据库的回复文本倒填结果。全量会话仍永久保存；新规划诊断只进程内保留，重启后不会重建旧记录。真实长期保留需要单独的持久化设计，本次不新增数据库表。
- 源码、配置修改必须重启 Runtime 并重新建立 Realtime Session 才能完整生效；现场正在运行的机器人不在本次自动重启范围内。
