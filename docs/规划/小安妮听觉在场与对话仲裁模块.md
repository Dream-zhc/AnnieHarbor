# 小安妮｜听觉在场与对话准入摘要

> 更新：2026-10-09。历史自训练方案与里程碑不再作为待开发队列；保留已经接线的sherpa-onnx KWS、状态合同和实测缺口。软件阶段已收束，后续只按具体Bug修复。

## 当前边界

- 待机由本地关键词检测处理，`SLEEP`期间PCM不送Qwen；唤醒后使用既有Qwen Realtime与独立TTS/ForcedAligner，不新增第二套ASR/聊天模型。
- 对話准入与输出许可分开：KWS命中只开启候选窗口，有效ASR及同轮epoch/item确认才允许回复/工具；提前到达的自动response必须缓存/拒绝，不能播完后仅删Chat。
- 模型权重可共享，每个robot的流、解码cache、PCM短缓存、计时与epoch独立。一Room一路PCM，不靠唤醒判断可靠说话人身份。
- 当前只保留sherpa中文预训练KWS，不自训练，不保留旧训练框架；权重在 `var/models/`，不入Git。关键词选择见[中文唤醒词说明](../规范/中文唤醒词配置说明.md)。
- 产品运行模式区分：本地待机唤醒；被授权的持续对话；环境语义理解。第三种需要明确授权及声源/成本证据，本期未默认实现，不把环境音偷偷转成Chat、记忆或工具。
- `SPEAKING/HOLD`是并行播放状态；5秒等待计的是开始讲话前，8秒追问由匹配的真实speaker drained开启，长句不能被窗口截断。时钟用服务器单调时间，重启/重连/退出递增epoch并撤销旧许可。
- 候选插话HOLD、无效恢复、有效清旧输出继续沿用已有Room协议；browser_test、生成结束、PCM发送完成均不替代物理speaker确认。

## 尚待现场确认

真实中文人声的召回/近音误触发/FPPH、距离噪声、唤醒词加问题不丢首字、窗口边缘长句、附和与环境声、误Hold恢复、有效插话、跨Robot回执隔离，以及真实Qwen自动response事件顺序仍须留证。没有声纹/多麦阵列或可信授权源，不能宣称旁人指向性、全时环境理解已实现。

物理扬声器须回传经过校验的turn/playback/epoch/seq/游标；模型缺失、推理积压或重连失败明确报错并封闭相应入口，不静默放开全时云端收音。误唤醒率目标须实际环境负样本时长和门槛确认，不用合成音频证明真人准确率。

## 已实施的软件与复测入口

### 已实施的软件链路

- sherpa-onnx Python 1.13.8 / numpy2；依赖进入 annie-adapters 与 uv.lock，默认懒加载（配置开启才初始化）。
- 官方2025-12-20中文/英文3M Zipformer chunk16/left64模型，存储在 var/models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20/；跨Win/Mac/Linux下载命令：uv run --locked python scripts/下载中文唤醒模型.py，校验官方发行包SHA256，不提交模型权重。
- config/小安妮唤醒词原文.txt 按官方text2token工具生成 config/小安妮唤醒词.tokens.txt：x iǎo ān n ī @小安妮；未通过自行拼音推测。
- apps/runtime的wakeword.py负责休眠态20ms PCM短缓存、100ms流式解码输入、模型推理异步任务、1秒预回放、5秒WAKE_WAIT与8秒真实speaker drained追问；packages/annie-adapters中的kws.py负责共享模型权重与按机器人独立stream，不能交叉共享decoder cache。超过0.5秒的推理积压**报错并封闭音频入口**，不静默旁路到Qwen。
- 原有 DialoguePresence 被接入 RealtimeRobot：Qwen auto-response提早到达时先在本回合内有界缓存，直到真正的ASR被准入；纯唤醒词、无效轮或环境转写丢弃自动输出，不执行工具、不播TTS、不新写Chat；失效响应尝试取消/删除未播输出。原有外部文本/事件路径不依赖唤醒门控。
- 正式speaker drained仅在当前唤醒授权的turn_id匹配时开启FOLLOWUP；网页browser_test回执不可替代。无TTS时回复结束直接回到待机；存在TTS但长期没有播完回执时设120秒异常保护，不把生成完成谎称为播完。
- 快照 wakeword 显示 backend/state/pcm_to_qwen/audio_reply_allowed/epoch/wakes/sleep_frames_rejected/error；不展示虚构性能数据。

### 如何启用与统一测试

1. 在本项目先运行 uv run --locked python scripts/下载中文唤醒模型.py。已完成下载的机器会直接提示模型就绪。
2. 保留原有 .env 的API Key和Room设置。当前本机已写入 ANNIE_WAKEWORD_ENABLED=1；关键词选用 ANNIE_WAKEWORD_KEYWORDS=config/小安妮唤醒词.tokens.txt（保守版）。不添加第二路Room麦克风。
3. ANNIE_WAKEWORD_MODEL 指向上述**模型目录**（不是某个ONNX文件）；ANNIE_WAKEWORD_THRESHOLD 默认0.35，为未单独指定阈值的关键词路径使用。要试14条宽松配置，把 ANNIE_WAKEWORD_KEYWORDS 改为 config/小安妮唤醒词_宽松实验.tokens.txt，重启服务。细节见 docs/规范/中文唤醒词配置说明.md。
4. 从现有工作台/状态API检查 wakeword.backend=sherpa-onnx、SLEEP与WAKE_WAIT变化，以及 sleep_frames_rejected、frames_sent、wakeword.error；休眠发送真实PCM后上云frames_sent不能增长。
5. 使用“小安妮”“小安妮今天天气怎么样”“小安宁”“电视播出安妮”以及两头并发/10分钟无人喊唤醒词/中途打断/播放后8秒追问实测；记录当轮转写、真实speaker回执、误触发、总延迟。

### 证据等级与剩余风险

- 已验证本机真实ONNX可创建解码流；静音输入两段没有触发；Mac系统合成的“小安妮”PCM经Sherpa原生解码及WakeAdmission非阻塞入口分别触发一次；这些是**合成音频冒烟**，不是中文真人召回/FPPH测评。
- 现有 FakeSocket 与测试PCM证明软件层拦截提前的response/text/tool，验证多头隔离、失效响应和回执条件；真实Qwen云端事件顺序、物理设备开始/结束播放及真实人声距离噪声依然待测。
- VP-07旁人指向性及VP-12授权环境理解**未因替换KWS而实现**；sherpa只做唤醒词检测，其他能力依靠既有Realtime/Runtime与未来可信声源/授权信息。
