# 行业调研与同流表达方案

2026-10-10。结论：默认应当是**符合语境的自然表达**，不是每句话都强烈兴奋。建议同一个 Realtime 主脑在同一次生成中先给表达意图，再流式给正文；独立 TTS 负责声音实现。此方案完成可行性试验，**尚未接入正式对话**。当前交付的修复仅涉及追问音频、语言跟随和诊断，不切换模型/音色/合成协议。

## 1. 用户旧脚本究竟测了什么

只读 `/Users/dream/Downloads/qwen_audio_tts_clone_full_test.py`：
- `build_test_cases()` 的自然与调皮兴奋用例有具体 instruction，后者强调聪明、兴奋、略带坏笑、调皮、灵活节奏，而不是一句“自由发挥”。
- `TestCase` 默认 rate/pitch=1、volume=50、seed=42；实际 `SpeechSynthesizer(...).call(case.text)` 一次提交整段文本，callback 流式接收 MP3。它没有 LLM 参与每句表达决策。
- 当前业务是 Realtime 增量文本→duplex 外置 TTS→24k PCM。输入时机、上下文可见长度、音色、seed 都可能影响结果；旧样本更好，不能仅归因为某一个因素。
- 原始与当前音色不同，当前匹配目录的 `重训1008`。未经同句听验，不断定重训一定更差，也不先切配置。

## 2. 官方资料支持的工程做法

- **Qwen** 把 instruction、rate、pitch、volume 等放在 `run-task.parameters`；`continue-task` 发送文本。自然语言指令控制方言/情感/角色，数值参数用于整体速度、音调和音量。当前合同没有在 continue-task 中更新风格的字段；因此一轮风格头不等于已经实现每句独立参数变化。[官方客户端事件](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-client-events)
- **ElevenLabs** 文档将上下文、音频标签、标点、声音选择共同视作表达控制，并强调合适的声音与样本、不同模型支持差异、具体声音需测试。标签不是跨厂商通用协议；把舞台说明直接混入正文还可能被朗读。[官方最佳实践](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices)
- **Cartesia** 提供流式 WebSocket、context_id、取消和时间戳，说明实时链路同时需要上下文与生命周期管理；表达增强不能丢失打断、文本/音频关联。[官方 WebSocket](https://docs.cartesia.ai/api-reference/tts/websocket)

工程归纳（本项目建议，并非声称行业都采用同一架构）：主脑决定“对谁、为什么、用什么态度说”；TTS 实现韵律；本地策略限制幅度；用同句听测校准，而不是给所有句子固定“开心+快+大声”。

## 3. 三条路线及延迟

| 路线 | 何时获得意图 | 代价/本项目判断 |
| --- | --- | --- |
| 只有默认 TTS 语义演绎 | 第一段文本到达 | 最少显式控制；当前 contextual 近似此路线，不是每句主脑规划 |
| 同一 LLM 同流短风格头→正文 | 同一次 response 的正文之前 | 无额外模型往返，但风格 token 本身耗时；推荐继续验证 |

## 4. 可复用试验提示词（未启用生产）

```text
你是小安妮，一位温暖、聪明、自然的对话伙伴。根据用户语言回复，表达符合语境。
在回复正文之前，第一行先输出紧凑 JSON，只含 emotion、pace、energy。
emotion: neutral/warm/playful/excited/curious/calm/serious/sad。
pace: slow/normal/fast。energy: low/medium/high。
按语境选择；不要将安慰表现成兴奋，不要把丰富表达理解成喊叫。
换行后直接输出自然回复正文，不输出 Markdown 围栏或舞台说明，不调用工具。
例如：{"emotion":"warm","pace":"normal","energy":"medium"}
```

落地设计要求：
1. 本地流式解析器需限制头长度/等待时间、校验白名单，头不可进入聊天正文、TTS文本和 ForcedAligner；缺头/错头/工具响应有明确回退且不重复首字。
2. 表达意图转成**具体指令**：比如“先轻快惊喜，后半句调皮、问句略上扬，避免喊叫和播音腔”。rate/pitch/volume 只作保守整体调节，不能代替语义韵律；待听验校准，不能把 high 机械变成满音量。
3. 用户显式语言/风格要求优先；Persona 保持稳定；取消、generation/session切换、工具调用及未播上下文修正必须沿用现有所有权。
4. 当前试验只是**每轮一个风格头**。要做到多句转折，需验证当前音色/duplex 对官方标签的支持，或明确采用多 TTS task 并检验连贯性、首响、嘴型和取消；不把 continue-task 文本分片假称独立风格段。
5. 先用选定音色做至少20组含开心、安慰、调侃、严肃、英文和方言的同句对照；比较具体instruction/整段输入/duplex输入，记录格式失败、P50/P95、实际PCM以及人工盲听。输入语音情绪旁路的识别另测，不混成TTS情绪验收。
