# Phase 5｜新一轮错答上一轮的返工与验收

## 问题与实证边界

用户报告“刚问新问题却收到上一轮的回答”。旧代码仅对重复的已接受 ASR final 做去重；如果旧 item 的 final、ambient 或稳定增量在新 item 的 speech_started 后才到达，可能误把旧文本当新轮，甚至取消新轮。单纯增加 Persona Prompt 无法修正输入归属。

本轮是工程竞态修复和可观测性补齐，未把用户报告的每次错答都归因为该竞态；真实模型也可能在正确输入下回错话题，须取证区分。

## 借鉴的实时交互工程原则

- [OpenAI Realtime 对话](https://developers.openai.com/zh-Hans/api/docs/guides/realtime-conversations)：语音开始、模型取消、音频实际播出位置和未播历史截断必须分开处理。该文档是设计参考；本项目使用 Qwen + 独立 TTS，并不假称实现了 OpenAI 私有协议。
- [LiveKit 轮次与打断](https://docs.livekit.io/agents/logic/turns/)：候选起声不等于有效语义轮，误打断应恢复，历史只保留用户实际听到的部分。
- [LiveKit 轮次调优](https://docs.livekit.io/agents/logic/turns/tuning/)：端点判定、可撤销投机输出、真假打断和预生成是不同维度；不能用固定增益阈值代替语义确认。

## 本轮最小修改

1. 新的带 item_id 的 speech_started 会将尚未确认的前一个 item 标为过期；其迟到的 stopped/delta/ambient/final 不再覆盖本轮 transcript、不再取消/启动 LLM。已接受 item 的重复 final 仍按原去重处理。最多保留 128 个过期 ID，Session 重建清空。未带 ID 的 Provider 事件无法安全判断归属，不能用时间猜测并假称完全解决。
2. 外置 LLM 在该轮任务建立前冻结实际 messages（含统一身份/Persona 指令、筛选的历史和**本轮输入**），避免任务排队时上下文悄悄变动。保留受机器人、Chat、Persona、epoch 和 generation 限定的 last_llm_input 快照，开发者工作台可折叠查看；不在运行日志输出对话或密钥。
3. 流式任务收尾和错误处理在异步边界后再次检查 turn_id/身份；失去所有权的旧任务不得替新轮写入 text.done 或完成 Ledger。
4. 统一 Persona 指令明确“当前输入是本轮唯一待答问题，历史只供指代/更正”，不为此加入每轮摘要、情绪识别模型、关键字话题路由或另一套语音服务。

## 实测判别与剩余缺口

自动化加入“旧 A 起声、新 B 起声、旧 A 的停止/增量/ambient/final 迟到、新 B 最终接受”“后台任务启动前历史变化不改变请求”等竞态。它们验证事件归属，不代替真 Provider 的连续多轮答复。

真机统一复测：在两个独立 Chat/Persona 中反复运行“喜欢茶 → 不是茶，是咖啡 → 那你推荐什么”，以及“讲故事 → 插话问别的问题 → 继续刚才”。每轮对照 ASR item_id、transcript.done 的 turn_id、last_llm_input 最后一个 user、模型 text.delta 的 turn_id、实际播出证据及延迟。如果新问题在实际 messages 中正确而模型仍回复旧题，应留样改进指令/历史选择，不再把它报作 ASR 竞态；反之优先修输入归属。

**未结项**：实际说到半句时的设备 sample cursor 与听到的文字对齐、没有 item_id 的 Provider 事件归属、真人多轮质量和延迟 A/B，不能用单测结果宣布完整 Phase 5 PASS。
