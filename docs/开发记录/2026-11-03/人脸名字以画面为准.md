# 人脸名字以画面为准：认得的脸不按报的名字录（2026-11-03）

用户要求：没有名字才能录，有名字就以画面为准，有姓名的意图就必须以画面为准，画面视觉描述不可用才根据上下文。已录的名字错了不支持当面改名，只能先让她忘掉再重录。

```text
本次问题与范围：11-03 16:58 实测，画面里认得是 B 的人说“我是 A”，remember_face 各道检查都放行，按 A 又录了一张脸（16:58:48 录完），她还回了“A，我记住啦”。另外，旧代码里“画面认得是 X、对方坚持叫 Y、再调用一次就按 Y 重录”的路径和用户规则冲突。
目标与用户可见效果：画面里认得的人，不管报什么名字都不录，她照画面的名字叫，并说明名字错了只能先忘掉再重录；只有画面里不认识的脸才录；画面不可用（5 秒内没有新的人脸观察）时才按报的名字录。忘掉后马上重录不会被画面里残留的旧名字挡住。
输入 → 处理 → 输出：识别终稿 → 模型 FC 调 remember_face → _tool_call 规则/D3 → faces.remember：取 room_monitor.people_view()（去掉 5 秒内刚忘掉的名字）→ busy / no_person / recognized / 单人认得 known_as_other / unavailable / already_known / 人多且正看着的人认得 known_as_other / 开始录 → 结果和说明回给模型。
改动文件：apps/runtime/src/annie_runtime/faces.py、apps/runtime/src/annie_runtime/realtime.py、packages/annie-adapters/src/annie_adapters/realtime.py、tests/test_face_registration.py、tests/test_loose_instructions.py。
保留项：规则优先、D3 兜底；不替别人录脸；遗忘要确认一次、只能忘掉此刻在面前认出的人；同音字匹配；【认人】规则（画面没认出的名字不用来称呼、不复述）不变；ANNIE_ADDRESSEE_ENABLED=0 及其默认值不变。
不做事项：当面改名；人多且没有注视标记时的判断（照旧录视觉端此刻注视的那张脸）；视觉端人脸库去重。
结果：人脸 16 个、宽松指令 28 个测试通过；全量 1341 通过、4 个失败均为既有问题（见《回复带人格、只答当前这句、不重复》文末）；重启主脑生效；真机待验。
```

## 1. 日志里发生了什么（名字不写）

| 时间 | 日志 | 说明 |
| --- | --- | --- |
| 16:57:21 | `instruction_decision kind=face_forget choice=yes`、`face_forget_confirm yes`、`POST /api/face/delete 202` | 用户说“忘记 A”，当时画面认出的就是 A，删掉了 A 这条记录 |
| 16:58:39 | `tool_call name=remember_face`、`GET /api/face/people`、`POST /api/face/register 202` | 用户说“我是 A”，各道检查都放行，开始按 A 录 |
| 16:58:48 | `face registration … state=completed` | 按 A 录完 |
| 17:00:04 | `vision_intent status=failed route=cloud error=cloud_timeout vision_wait_ms=1512` | 去看画面那次云端 1.5 秒超时；看失败时她只剩每秒一次的本地画面（含人脸识别名字） |

“认得是别人”那道拦截（known_as_other）原来只看 `people_view()` 的 `gaze_name`：必须是被标成注视目标、而且认得的人。房间监视器把短暂漏检的人沿用上一帧时会清掉注视标记（`room_monitor.py` 的 `dict(track["row"], gaze=False)`），这时画面里明明只有一个认得的人，`gaze_name` 也是 None，于是放行录入。当时的画面快照没有写进日志，无法确认是这一种，还是快照已过期（超过 5 秒）。

## 2. 改了什么

| 位置 | 改动 |
| --- | --- |
| `faces.py` `_remember` | 画面里只有一个人且认得（`gaze_name`，或 `count==1` 时唯一的已认识名字），就返回 `known_as_other`，不录；放在查人脸库之前，画面优先于“记过这个名字” |
| `faces.py` `_remember` | 人多时正看着的人认得，仍返回 `known_as_other`，请要记的人站到正前方；放在 `already_known` 之后（11-02 19:07 那种“记过、在侧面没认出”的情况仍按 already_known 提示） |
| `faces.py` | 删掉 `RENAME_CONFIRM_SECONDS` 和 `self.renames`：不再有“坚持就重录” |
| `faces.py` `_known_as_other` | 单人：“画面里你认得TA是X，以画面为准：不记，也不要用Y称呼TA。用一句话告诉TA你认得TA是X；名字要是记错了，只能先让你忘掉TA的脸，再重新记。”人多：请要记的人站到正前方、正对着你再说一次 |
| `faces.py` `FORGOTTEN_SECONDS=5`、`self.forgotten`、`_unforgotten` | 视觉端接受删除后 5 秒内，录入时把刚忘掉的名字从画面里去掉（房间监视器要连续 3 次观察、约 3 秒没认出才撤名字）。最初定 30 秒，用户认为太长（算法那边删了立即就不认），改为 5 秒。删除 10 秒内没确认时同名窗口也撤掉；窗口现在只有 5 秒，这条只在调长窗口时起作用 |
| `faces.py` `remember` | 每次录入写一行日志：`face remember robot=… status=… people=… known=… gaze_known=…`（只有人数和认没认出，不含名字） |
| `realtime.py` 会话指令人脸段 | 加“名字以画面为准：只记画面里还不认识的脸，画面认出TA是谁就照画面的名字叫，TA报的名字和画面不一样也不改口、不附和；已记的名字错了只能先忘掉再重新记，不能当场改名。” |
| adapters `remember_face` 描述 | 加 only if you do not know it yet；a wrong name is fixed only by forgetting the face first and recording it again |

画面不可用（`people_view()` 为 None）时仍按报的名字录，对应用户说的“画面视觉描述不可用才根据上下文”。称呼上【认人】规则不变：看不到画面时她不知道面前是谁，不用自报的名字称呼对方。

## 3. 测试

- `test_the_picture_s_name_stands_and_a_wrong_one_is_forgotten_then_filed_again`：画面里只有张三且没有注视标记，说“我是李四”→ known_as_other，说明里有“先让你忘掉TA的脸，再重新记”；坚持再说一次仍不录；忘掉张三（确认一次）后，画面还残留张三时说“记住我，我叫李四”→ 开始录；工具描述和会话指令里有新说法。
- `test_a_forget_that_never_lands_leaves_the_picture_s_name_in_force`：视觉端接受删除但张三一直还在库里，删除未确认后再说“我叫李四”→ known_as_other，不录。
- `test_loose_instructions.py::test_a_face_known_by_another_name_keeps_the_picture_s_name`：原“问一次、坚持就重录”改为第二次仍 known_as_other。
- 原有的人多、侧面认出、同音字、already_known、忘掉流程测试不变且通过。

## 4. 注意

16:58:48 那次已经按报的名字录进了一张脸。如果同一张脸原来还有另一条记录，人脸库里就有两条，画面可能时而认成这个、时而认成那个。被认成错的名字时，让她“忘掉我”（确认一次）就能删掉那一条。
