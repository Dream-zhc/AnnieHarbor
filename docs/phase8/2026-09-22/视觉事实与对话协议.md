# 视觉事实 v2｜给算法与 Room 发布端

## 目标与边界

- 现有 `roomv2/reb_visualllm`、`type=visualllm`、`description` 保持不变；旧发布端无需升级。v2 可选增加 `schema_version:2`、`facts`，不改 `reb_visualdata` / `reb_vision`，不传原始图像，不另启 LLM。
- 算法只交付**观察事实与明确标注的不确定性**，不要直接生成「小安妮」口吻、玩笑、安慰、提醒或命令。自然应答由现有 Qwen-Audio Realtime 结合当前 Chat 与 Persona 产生。
- 每条消息是一次**完整场景快照**，不是部分差量；发新消息替换旧上下文，断线和接收后超过 10 秒自动撤销。`changes` 只是辅助事实，不得替代本帧主体。

## 兼容载荷示例

```json
{
  "type": "visualllm",
  "schema_version": 2,
  "description": "画面中一人坐在桌前，右手拿着麦克风，桌面有电脑。没有证据确定是否正在录音。",
  "facts": {
    "subjects": [
      {"id": "person_1", "kind": "person", "attributes": ["坐着"], "action": "右手拿着麦克风", "position": "桌前", "confidence": 0.94},
      {"id": "mic_1", "kind": "microphone", "position": "person_1右手"},
      {"id": "computer_1", "kind": "computer", "position": "桌面"}
    ],
    "relations": [{"subject": "person_1", "relation": "holds", "object": "mic_1"}],
    "uncertainties": ["无法仅凭画面确认是否录音、唱歌或直播"],
    "changes": []
  }
}
```

`description`：可独立阅读的完整自然中文观察，必须有主要主体、动作、关键物品和关系；不要只写“画面正常”或只输出对象列表。不要将意图、情绪、职业或身份当成已知事实。`facts` 为可选；没有足够置信度时宁可只有 `description`，也不要伪造属性。

`subjects`：本帧重要的人/物；同一段连续追踪中 `id` 稳定，追踪丢失后不可假定仍是同一人，更不可将 `person_1` 认定为当前 Chat 用户。`kind` 是对象类别，`attributes` 是看得到的属性，`action` 是可见动作，`position` 是相对位置；`confidence` 可选且只表示相应主体的视觉可靠程度，不是身份匹配分数。

`relations`：显式主谓宾引用已列主体 ID；`uncertainties`：把无法确认的推测单列；`changes`：只有连续观察有依据时写可见变化，否则空列表或省略。不要用泛泛的“可能很开心”“准备唱歌”替代动作。`subjects` 上限 12，`relations/uncertainties/changes` 各上限 16；多余细节优先写入 `description`，保证主语没有被压没。

## 不丢主体的传输与预算规则

1. **Room WebSocket 不负责摘要或删字段**；如果上游先把画面压成一句话，后端不可能恢复被算法删除的人、物体或左右关系。请算法保留自然描述和主体关系，不要只发标签或单帧变化。
2. 当前 Runtime 保留 `description` 前 **4000 字符**用于工作台诊断；交给 Realtime 的**总视觉上下文最多 2000 字符**，有 `facts` 时先保留 `description` 前 **800 字符**，再附结构化事实 JSON（上限 **1100 字符**）。旧格式可使用前 2000 字符。这里是模型上下文预算，**不是无损的全帧档案**；超过限制的内容可能不会被主脑看到。
3. 超限或无效 `facts` 时沿用 `description`，并在 `/room-observations` 的 `visual.facts_accepted=false`、`visual.context_truncated=true` 暴露；描述被截断同样置 `context_truncated=true`。算法上线前应保证 `description` 重点在前且 `facts` 紧凑，避免经常触发降级。
4. 到期时间由本机 Room 接收时钟判定，**不信任算法端时间戳**；不同机器人按各自 Room 隔离。断流或视觉过期后，模型不应继续自称“现在看到”。

## 输出示例与验收

- 用户问「你看到了什么」：先说「你拿着麦克风，旁边有电脑。」在轻松氛围里才可顺势接一句「准备开唱呀？」；唱歌是疑问，不是观察事实。
- 用户问「我现在在录音吗」：若视觉只有“拿麦克风”，应答「看见你拿着麦克风，但单凭画面没法确定有没有在录音。」
- 用户问无关话题：不主动带入麦克风；切断视觉后不冒充仍有当前画面；多人物时不要把 `person_1` 直接叫成“你”。

该协议不宣称主脑具有原视频理解能力或自动主动开口，也不把 Fake Qwen 单测当成真实口语效果验收。
