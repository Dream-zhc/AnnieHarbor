# 音色克隆与会话切换

## 实现口径

- 设置入口：React 工作台「⚙️ 设定 → 音色克隆与管理」；上传清晰的 WAV/MP3/M4A 参考音频，最多 10 MB，备注 1~40 字。WAV 进一步检查 16 bit、至少 16 kHz、5~60 秒；MP3/M4A 由百炼进一步校验实际时长。只允许复刻本人或已获授权的音色。
- 云端：按用户上传的克隆脚本原理，服务端使用短期 OSS 上传策略与 voice-enrollment 的 create_voice，绑定 qwen-audio-3.0-tts-flash。不把密钥、原始音频或临时 OSS 地址存入数据库/浏览器。密钥仅取既有服务端 API 环境配置。用户上传脚本包含明文 Key，须自行轮换，不复制到仓库。
- SQLite：版本迁移包含 cloned_voices 和 voice_preferences，保存 voice_id、备注、创建时间与机器人/Chat 音色偏好。机器人级默认、Chat 覆盖两层；Chat 切换不丢失原有记录。移除某音色时清除其本地选择与缓存试听，但云端模型需要通过供应商管理能力另行处理。
- 试听：创建完成后异步串行生成 15 项 WAV，缓存在忽略 Git 的 var/voice_previews/ 下。既有原生 TTS WebSocket run-task 使用同一模型/音色、instruction、速率与音调参数，不向 Room 推送 PCM；包含普通话、河南/四川/粤语/东北/上海、英语、俄语、情感标签、富语言标签、自然语言 instruction、快慢速与耳语。需以实际听感核验模型对标签、方言和多语种的支持程度；**该实现复用现有 raw WS 协议，不宣称与上传脚本的 SDK 单向流试听完全等价**。
- 对话切换：Realtime Session 提供 select_voice(voice_name,scope)，仅接受用户当前轮明确说出的已克隆名称或恢复默认；通常为 scope=chat，用户明确「以后都用、所有会话」才允许 scope=robot。不通过 LangGraph 增加延迟，不允许 LLM 根据情绪、方言或人格自行换音色；设置页同样可明确切换。
- 生效：SpeechOutput 在下一轮 TTS run-task 前同步锁定 voice_id，当前已经合成/正在播放的 PCM 不换音；嘴型 ForcedAligner、音频 Room、打断链路保持现有协议。用户直接在设置页切换时不重启 Realtime Session。
- 诊断：FC 的 tool.called/tool.result 记录可查切换请求与受理结果；实际 TTS 参数诊断不暴露私有 voice_id，音色库设置页显示友好名称与当前生效选择。

## 验证边界

- Python 单元 / ASGI 仿真：实际参考 WAV 校验、假厂商复刻、持久化和跨 Chat/机器人隔离、FC 选择、越界会话拒绝、改名、本地删除、WAV 预览。
- 前端：TypeScript 检查、Web 测试、正式 Vite 构建，15 种试听卡片。
- 真正的百炼音色训练、所有 15 类试听效果、音色切换后的真实扬声器与音素同步 **需要用户在联网 Runtime 上手工验收**。本次不使用用户暴露的 API Key 主动进行收费调用。
- 工作区另有其他并行开发修改：仅更新本功能范围，未主动重启现场 Runtime 或覆盖其他并行文件。

## 自动化结果

- 完整 Python 测试：817 passed、42 subtests passed、2 warnings；另补充真实格式音色 ID 含小数点的校验后，音色与 TTS 定向回归 33 passed。
- 网页测试：99 passed；TypeScript、Ruff、`uv lock --check`、`git diff --check` 全部通过；Vite 正式构建成功，保留已有大 chunk 警告。
- 所有云端克隆与试听均使用模拟提供者进行自动化验证，未使用生产密钥发起计费请求；无真机播放验证。
