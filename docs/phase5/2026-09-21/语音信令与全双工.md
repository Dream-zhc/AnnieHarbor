# 全双工信令｜同 Room 新增 reb_voice

## 地址不迁移

仍使用 `roomv2`，**不是另建 `roomv2-voice`**。只有一条新增的 JSON 信令通道：

| 地址后缀 | 原用途 / 新用途 |
| --- | --- |
| `/robot/roomv2/reb_mic` | Win 麦克风原有 16k PCM，不变 |
| `/robot/roomv2/reb_tts` | Brain → Mac 原有 24k PCM、旧播放器兼容的 hold/resume/stop，不变 |
| `/robot/roomv2/reb_sam` | 音素，不变 |
| `/robot/roomv2/reb_main` | 原有动作、视觉等，不变；过渡期仍接受旧版播放回执 |
| **`/robot/roomv2/reb_voice`** | **新增：麦克风状态、云端语音判断的转发、Brain 播放控制、Mac 播放回执** |

URL 主机/端口沿用 `config/rooms.toml`。Room 服务器必须能为 `reb_voice` 返回 `WELCOME robotId=reb_voice`，并支持 `SUBSCRIBE` 与广播 JSON；**只改 Brain 的配置不能替远端 Room Server 创建新通道**。其他 Room 如 roomv3 仍按当前配置推导同名通道，不跨机器人混用。

## 事件、发送方和执行者

| type | 事件源 | 实际写入 reb_voice 的发送方 | 接收/执行方 |
| --- | --- | --- | --- |
| `mic.capture.started/progress/stopped` | 板端 `room-speaker --mic` / 网页麦克风 | `data.sender=source=microphone`，带 `instance_id`、`host`、`device_name`；progress 每 1～2 秒（2026-10-16 起） | Brain：诊断与“一 Room 一麦克风”提醒，不代替 Qwen VAD |
| `speaker.presence` | 板端扬声器 / 网页调试扬声器 | `sender=speaker` 或 `browser_test`，带 `instance_id`、`state`；每 2 秒（2026-10-16 起） | Brain：“一 Room 一扬声器”提醒；不是播放回执，不推动 AEC |
| `voice.interaction` (`speech.started/stopped`、`transcript.*`) | Qwen-Audio Realtime smart_turn/ASR | `data.sender=brain`，`trigger_source=qwen_realtime` | Mac、Brain 诊断；**阿里不直接连 Room** |
| `tts.playback.hold` | Qwen `speech_started` 候选 | `sender=brain`，`trigger_source=qwen_realtime` | Mac：约 40ms 渐弱，冻结游标、保留 PCM |
| `tts.playback.resume` | Qwen `turn_invalid` 或无效 ambient | `sender=brain`，`trigger_source=qwen_realtime` | Mac：原位约 120ms 渐强 |
| `tts.playback.stop` | Brain 已确认有效插话 / 手动取消 / Session 切换 | `sender=brain`，`trigger_source` 区分 Qwen / runtime | Mac：清旧 epoch 未播队列，停止旧音频 |
| `tts.playback.started/progress/held/resumed/stopped/drained` | Mac 输出线程 / 浏览器 AudioWorklet | 真正实体端 `sender=source=speaker`；网页 `sender=source=browser_test` | Brain：按 turn、epoch、playback_id、seq 和样本游标核对 |

Brain 只在选定的 Qwen 事件上发送 `voice.interaction`，**不把每个 PCM 帧或每个 ASR delta 广播到信令房间**。网关发送失败记 `voice.signal.error`，不是假装扬声器已经处理。控制命令同时镜像到旧 `reb_tts`，兼容未升级播放器；新播放器按同一个 `conversation_id+stream_epoch+command_seq` 去重，不能因此执行两次。

网页试听不再向 `reb_voice` 周期广播 `tts.playback.progress`：Worklet 的高频游标只更新网页本地状态，`started/held/resumed/stopped/drained` 仍携带实际游标回传。避免把播放进度误当心跳并淹没 Room 消息；不需要新建第二个 Room 或改动现有控制链。外置 Mac 播放器若仍周期上报进度，须在其自身程序里同样停发或降频，Brain 无法代它阻止 Room 先广播。Brain 与网页新增 `description` 中文字段，紧跟 `type`，再是 `ts`；其余解析仍以 `type/data` 为准，Room 服务端重包装时字段排序不作协议保证。

### Brain → reb_voice 的起声消息

```json
{"type":"voice.interaction","ts":0,"data":{"sender":"brain","trigger_source":"qwen_realtime","event":"speech.started","robot_id":"annie-a","item_id":"provider-utterance-id","conversation_id":null,"text":""}}
```

### Brain → reb_voice 的暂停指令

```json
{"type":"tts.playback.hold","ts":0,"data":{"protocol_version":1,"conversation_id":"turn-a","stream_epoch":1,"command_seq":1,"reason":"speech_started","sender":"brain","trigger_source":"qwen_realtime","fade_ms":40}}
```

### Mac → reb_voice 的暂停回执

```json
{"type":"tts.playback.held","data":{"protocol_version":1,"conversation_id":"turn-a","stream_epoch":1,"command_seq":1,"played_sample_count":480,"sample_rate":24000,"seq":2,"source":"speaker","sender":"speaker","playback_id":"mac-output-1"}}
```

恢复回执为 `tts.playback.resumed`，同样回显 `command_seq`。`started/progress/stopped/drained` 仍使用[播放端 WebSocket 协议](../../phase4b/2026-09-20/播放端WebSocket协议.md)的采样游标字段。回执报告 **输出回调消费的 24k 等价样本**，不得用收到的网络包数伪造。网络断开不表示 `stopped`。网页试播只能自报 `browser_test`；它的 held/resumed **不会把 Brain 的扬声器物理状态升级为已确认**。

## 本次代码交付边界

- `speech_started` **候选**暂停，不能直接当成有效用户意图；无效 ASR/ambient 恢复，确认后的新输入取消旧 TTS；不新增本地能量打断裁决。
- 网页调试播放器的真实 AudioWorklet 采样进度可以按 `browser_test` 回传；浏览器渐弱约 40ms、原位渐强约 120ms。WebSocket 不通仍可试听，但回执保持未知。
- **用户当前另行运行的 Mac 独立 WebSocket 播放程序不在此代码仓库内；必须按上表实现音频线程回执才会出现 `speaker` 物理回执**。Brain 不会替 Mac 伪造。此阶段不改 AEC、不改 PCM 和音素 Room 路由。
- 同 Room 帧协议不认证真实发送方，`sender/source` 是自报；实际设备身份可信度依赖 Room 网关认证或设备证书，现阶段不能称声学硬件验收通过。
