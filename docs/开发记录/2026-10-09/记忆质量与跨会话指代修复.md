# 记忆质量与跨会话指代修复

## 原因

- 2026-10-09 15:06 的「我最近去准备去看车」是 Schema 9 升级前的来源未知回合，15:53 的「你有推荐的吗」为新文字回合；二者 Chat 相同、Realtime Session 不同。旧历史回复不能未经扬声器证据直接当作已播出。
- 历史恢复原先只保留无播音证据的用户原话，却没有突出最近明确的未完话题；模型没正确把「推荐」指向「看车」。
- LangMem 旧接口只看单句，分类校验接受了「北京的」被推断为所在地、含糊偏好、一次性提醒和重复的日常情绪事件。

## 修复

1. 同一 Chat 近期历史中存在明确的准备看车等计划时，生成只用于指代消歧的临时话题锚点，供新 Realtime Session 理解模糊提问；不恢复未经设备回执的助手语音，也不重放历史任务。
2. 异步记忆抽取额外带入同一 Chat 最近两个已完成问答（截断），仅用于本轮用户原话消歧；助手之前说的内容不得独立变成用户长期事实，且不增加普通聊天的模型请求。
3. 拒绝不完整偏好、无证据的居住地归因、一次性提醒命令、伪造的角色好感、单日疲惫及重复无意义事实。
4. 明确的「最近准备看车」按已有 episodes 作用域存为统一 fact_key=ongoing_plan_car_viewing，限 30 天并保留原话 turn_id。对方确认已经买车、放弃看车后更新为已结束，不再当作待办。计划可跨同一角色的 Chat 召回；当前仅优先闭环「看车」，没有建立一套未经测试的通用事项引擎。
5. 仅在已选择积极续聊且**网页文字交谈**中用户主动寻求话题时，短时规划器才可接收仍有效的计划；实体扬声器/公共环境继续禁止通过空闲主动规划暴露私人计划。
6. 网页把规范化记忆「用户最近……」显示为「你最近……」，SQLite 中仍存中立第三人称。旧的有问题的记忆仍在库中，可人工审核、更正、遗忘；已经识别为无证据的条目不进入 bootstrap/recall。

## 验证与限制

- 单元：相邻问答、不同 Session 的旧话题线索、稳定作用域/去重、30 天跨 Chat 计划及完成后的停止、提醒/地点/人称过滤、前端显示。
- 完整回归可能受现有并行未提交的唤醒词代码影响；区分本次定向测试与全量结果，不能把不相关的失败写为通过。
- 缺少身份认证的共享网页或扬声器仍无法证明用户身份；不能把私人计划交给基于摄像头单人检测的 8C 公共场景发声。
