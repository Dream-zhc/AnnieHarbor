# 云端唤醒与交互准入（2026-10-08）

## 已接线（代码回归，不等于设备验收）

- 单 Runtime 使用一份可选的 `livekit-wakeword` ONNX 推理实例；每个 robot 独有 PCM 环形缓存、状态、超时与计数。
- 每路 Room PCM 保留原有 16kHz/16bit/mono 契约；休眠 PCM 只送云端唤醒检测，不送 Qwen Realtime。Wake 成功后继续复用现有 smart_turn 和 TTS HOLD/Resume。
- 状态：`SLEEP` → `WAKE_WAIT`（5s）→ `ACTIVE`（最长30s无播放回执的保护窗口）→ `FOLLOWUP`（扬声器 `drained` **真实**回执后8s）→ `SLEEP`。在 `FOLLOWUP` 期间检测到 Qwen speech_started 可重新进入 `ACTIVE`。
- 唤醒检测用最近2秒音频，每0.5秒最多判一次；命中时回送结尾240ms缓存（12个20ms/640字节帧）以降低紧邻首句的截断风险。该缓存无法精确定位唤醒词结束，是否导致多余回复仍待设备验证。
- 不再把 `ambient_audio_transcription.completed` 按文本猜测升级为用户回合，避免环境聊天直接引发本地 `response.create`、Chat写入、动作。
- 未配置模型时唤醒功能默认关闭，旧热路径不变；显式开启但模型缺失/推理包未安装时报错，不静默退回持续上送。

## 启用条件

1. 在**独立训练环境**按官方 VoxCPM 中文路径运行 `config/唤醒词训练.yaml`，导出 `xiaoannie.onnx` 并离线评测。需单独安装对应训练依赖；生产 Runtime 不安装训练依赖。
2. 将通过评测的模型存入本机 `var/models/xiaoannie.onnx`（不提交权重），在 Runtime 虚拟环境安装可选推理包 `livekit-wakeword==0.3.0`。
3. 将 `.env.example` 中的 `ANNIE_WAKEWORD_ENABLED=1`、`ANNIE_WAKEWORD_MODEL=var/models/xiaoannie.onnx` 及阈值加入私有 `.env`；从 React 工作台测试两个机器人各自 Room。

## 尚未完成／不能声称已解决

- **中文唤醒模型未训练、未评测。** 合成中文训练数据不足以代替真人近音词、方言、真实房间、噪声、远场与回声验证；阈值 `0.5` 只是初始参数。
- **不是说话人身份识别。** 单路混合 PCM 不能证明哪个人在说话；8秒 FOLLOWUP 内旁人插话仍可能被 smart_turn 接受。严格解决必须新增声源/身份可信证据，不能仅靠正则文本。
- **缺少真实音频端到端证据。** 需验证连续唤醒与首句同气息、仅喊小安妮不误答、两机器人双路并发的误唤醒/漏唤醒/CPU/P95、真实 speaker `drained`、重连、超时和打断。
- 唤醒模型读取的2秒 PCM 含麦克风环境声，短期缓存只在内存且不持久化。休眠时不向 Qwen 发送 PCM，但实时 WebSocket 仍保持连接（沿用项目原本的15分钟闲置回收机制）。

参考：`https://github.com/livekit/livekit-wakeword` 官方 README 的中文 VoxCPM 训练和 ONNX 推理指南。

## 2026-10-08 专项调研与下一步实施次序（只定方案，尚未执行训练/真机）

### 外部依据与版本

- Google Assistant Continued Conversation：官方说明设备可在回复后约8秒内接受追问；另一个帮助页说明约10秒，还结合语音与姿态传感器。资料：https://support.google.com/assistant/answer/9249169 、https://support.google.com/assistant/answer/10004407 。不能当作所有场景的统一超时常数。
- Alexa：利用声学、部分设备上的视觉信息判断语音是否在对设备讲话；仅检测到语音不能证明是指令。资料：https://www.amazon.science/blog/change-to-alexa-wake-word-process-adds-natural-turn-taking 。
- LiveKit Agents：将端点检测、误打断恢复、设备指向判断分层；推荐参考误打断后恢复，而不是整套引入第二条ASR/模型主链。资料：https://docs.livekit.io/agents/logic/turns/adaptive-interruption-handling/ 。
- `livekit-wakeword` Python 0.3.0（PyPI 2026-09-30）：`WakeWordModel.predict()` 为**无内部PCM缓存**的约2秒16k PCM窗口推理；官方客户端示例通常在设备端运行，本项目保留“Room PCM→云端推理”的不同部署形态。中文训练建议使用 VoxCPM2，并明确警告中文准确率低于英文；官方推荐增加发音多样性、50～100个声音描述、样本数量与中文手写负样本。资料：https://github.com/livekit/livekit-wakeword/blob/main/README.md 、https://github.com/livekit/livekit-wakeword/blob/main/configs/prod_voxcpm.yaml 、https://github.com/livekit/livekit-wakeword/blob/main/docs/export-and-inference.md 。
- Qwen-Audio Realtime `smart_turn` 能自动触发回复，`conversation.item.ambient_audio_transcription` 不可被提升为用户轮次；`turn_detection` 开始送音后不能在线切换。当前官方资料还支持可选 `voiceprint_audio_urls`（`smart_turn`，至多5个音频URL）做目标说话人增强，但不是可靠身份认证，且涉及语音样本公网可访问的隐私风险。资料：https://help.aliyun.com/zh/model-studio/fun-audiochat-realtime-websocket-api 、https://help.aliyun.com/zh/model-studio/fun-audiochat-client-events 。

### 推荐交互产品语义（待现场调参）

1. `SLEEP`：保持麦克风到KWS，不向Realtime转发休眠音频；Chat/长连接可继续存在。
2. `WAKE_ACK`：KWS检测到“小安妮”只驱动轻量提示音/目光/LED（若已有可用协议），不直接让LLM朗读唤醒词，避免仅喊名字就乱答。
3. `WAKE_WAIT`：唤醒确认后5秒内须检测到**指令语音开始**；一旦开始，等待完整回合，不能5秒到时砍断用户话。连续说“小安妮，今天怎么样”需尽量无缝保留首句。
4. `ACTIVE`：经准入的语音由既有 Qwen `smart_turn` 判轮；生成和播放持续期间不能被无关的30秒硬超时取消。对工具、记忆和动作严格限定于有效用户回合。
5. `SPEAKING`：候选插话只发HOLD；确认有效后取消TTS/嘴型与未播上下文，`turn_invalid`/环境音则Resume，不能因简单声音立即Cancel。
6. `FOLLOWUP`：**真实speaker drained**之后开8秒；用户明确仍在对小安妮提问则无需重唤醒并启动下一轮；边界处开始讲话就保护整段语音，不能8秒截断。长期无声、明确说“退下/不用了”、停止服务则回`SLEEP`。`browser_test`回执绝不可当作设备实际播放结束。
7. 多人：初版为“单Room单路混合PCM”，不能保证分辨谁在对机器人说话。可选先试 Qwen 说话人增强与已有声学/视觉证据，但在有效性证据不足时采用保守门控（短追问窗口、无效附和不写Chat、不执行动作），不能宣称已解决旁人交谈。

### 现有实现与设计差距（下一阶段优先）

- 当前 `WakeAdmission` 的5秒、8秒和30秒仅为固定时钟：`speech_started` 尚未可靠区分唤醒词尾音和正式问题；`ACTIVE` 的30秒超时可能碰上正在说话、思考或播放，实际需要状态分层及独立看门狗。
- KWS采用2秒窗口、500ms检查间隔、240ms预回放；没有音素级唤醒词终点，也没有真实“唤醒+同气息提问”验证，可能丢首字、把唤醒词尾巴提交Qwen，或让Qwen自动回答唤醒词。
- `_audio_pump` 当前等待同步的KWS推理结果才继续消费PCM，尽管放到线程，双机器人大负载仍可能导致队列堆积/过期。改为每头最新窗口、单共享推理限并发、独立有界结果队列的非阻塞调度，并以实测P95和丢帧率作决策。
- `smart_turn` 自动回合有时早于最终ASR；事后过滤文字不构成前置回复准入。需针对迟到 `response.created`、`response.text.delta`、ToolCall、超时、重连建立严格 epoch/turn 绑定并回归。
- `config/唤醒词训练.yaml` 是最小起点，尚没有针对中文的 `custom_negative_phrases`、声音多样性、方言和独立真实录音验证，不能直接投入训练后宣称可用。
