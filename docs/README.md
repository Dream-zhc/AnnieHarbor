# 文档入口与优先级

本文件用于限制AI和开发者的默认阅读范围，避免历史记录覆盖当前设计。

## 先按问题定位，不通读全部技术章节

- **想知道每阶段做什么、做完什么效果：** 看总计划开头“先看这里：业务边界与阶段效果”。
- **准备执行某阶段：** 看总计划第25节对应任务卡和第32节开工模板；先复述目标与未决问题再改动。
- **想知道实际完成了什么：** 看对应阶段README的证据；规划要求和历史样例不是完成证明。
- **有架构/协议疑问：** 按任务卡引用再查具体章节，业务语义查证后仍不明确就问用户，不自行改目标。

- **正式前端从何时开始、后续在哪里加功能：** 看总计划第22节React工作台范围与第25节Phase 4C任务卡；复用Phase 4/4B现有接线，4C完成基础/前序功能/布局整合，后续统一在`web/`迭代，临时HTML不替代正式功能。

- **网页怎样才算验收通过：** 总计划第22.5节列WEB-01～08共同门槛，第25节Phase 4–11任务卡列网页操作→预期→证据；规划先列用例，实施后填实际结论。

## 默认只读

1. `PROJECT_RULES.md`：最高优先级工程规则。
2. `docs/规划/小安妮V2后端开发总计划.md`：唯一阶段路线图与当前架构方向。
3. `docs/规范/项目结构与配置规范.md`：当前目录、配置和运行数据规则。
4. `AGENTS.md`：执行入口和当前阶段提醒。

## 按任务读取

- 外部协议、Room、小脑、设备、兼容性：读`docs/phase0/2026-09-17/`中的README、External Contract、协议清单、行为清单与fixtures。
- 核对已完成Phase 1骨架：读`docs/phase1/2026-09-17/README.md`。
- 处理Room PCM、来源绑定或真实Room联调：读`docs/phase2/2026-09-18/README.md`。
- 核对Phase 3会话、Persona、Ledger、20轮上下文或TurnCoordinator：读`docs/phase3/2026-09-18/README.md`。
- 核对Phase 4正式工作台与Realtime已有证据：读`docs/phase4/2026-09-20/README.md`；4B正在开发，本次不改其实施范围。
- 规划Phase 4C网页基础、前序功能接齐及布局验收：读总计划第22.1/22.5节与第25节4C任务卡；4C实施记录在开工后创建，不把规划当通过证明。
- 其他任务不要默认递归扫描整个`docs/`。

## 文档保留规则

- 计划只保留总计划和当前阶段必要方案，阶段完成后删除重复的临时实施计划。
- 阶段目录只保留一个摘要README和仍有回归价值的合同/fixture；红绿日志、命令转储、完整源码快照、重复diff和已完成迁移审计默认删除。
- 当前代码、配置和自动化测试优先于历史阶段文字；历史阶段文档不得反向定义当前架构。
- 新的架构决策直接更新总计划/规范，不再保留已废弃实现的源码、配置或“兼容占位”。
- 不保留空目录、占位文件、中英文同义目录或仅供历史追溯但已无协议/回归价值的文件；目录在第一个真实文件落地时再创建。
- Phase 1–5（含4B/4C）沿用`tests/html/`临时验收安排；Phase 6及以后不再新增独立HTML测试/验收页，直接在现有React工作台集成功能并完成网页验收，证据写阶段README。既有临时页按Phase 10最终整合安排、用户确认后删除，后续不重建；自动化、浏览器及真实/人工验收要求不变。
