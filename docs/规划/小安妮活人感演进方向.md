# 小安妮｜方向评估与活人感演进建议

> 编写：2026-10-26。**本文是方向建议，不是开工任务卡。** 2026-10-26 用户安排的第一版（4.1 评测脚本、4.2 中“她自己的一天”、4.3、4.4 的素材部分）见[内在生活第一版](../开发记录/2026-10-26/内在生活第一版.md)，其余未排期。 软件阶段冻结、Phase 10/11 及后续暂停仍然有效；以下任何一项开工前都要用户明确排期，并按[总计划](小安妮V2后端开发总计划.md)的 Bug/阶段模板复述目标与验收。现行边界以 [PROJECT_RULES](../../PROJECT_RULES.md) 为准，本文不改变任何已确认规则。

## 1. 结论

大方向正确，工程底子比多数同类开源项目扎实。需要转向的是**演进方式**：近一个月每个现场问题都靠补一条正则或一句提示词解决，这和“越来越聪明、像人”是反方向的。后续应先建立对话质量评测闭环，再逐步把规则换成可评测的模型判断，并补上“她自己的经历、关系、内在状态和动机”。

## 2. 现在做对了什么（继续保持）

- **快慢脑分离**：普通聊天只走 Qwen Realtime（听写、轮次、对话、Persona、Function Calling），LangGraph、记忆抽取、决策模型都在旁路异步。业界在全双工语音上也在走“前台实时模型 + 后台工具”的拆分。普通聊天不要回到多步 Agent。
- **独立 TTS + ForcedAligner**：放弃了端到端语音的副语言能力，换来音色、方言、嘴型可控，对实体机器人是合理取舍。
- **“生成 / 发布 / 真正播出”分开**：Ledger、epoch、`source=speaker` 播完回执、打断时撤销未播上下文。这是不接错话、不抢话的地基，很多开源项目没有。
- **记忆可更正、可遗忘、防复活**；用决策模型判断“是不是在跟我说”；用真实演示原话标注做模型对比（见 [d3 决策模型评测](../开发记录/2026-10-21/d3决策模型评测.md)）。这些方法都对。

## 3. 需要警惕的问题

| 问题 | 现状证据 | 影响 |
| --- | --- | --- |
| 规则补丁在堆积 | `apps/`、`packages/` 中约 95 处中文正则；`memory.py` 为“看车”单独写了 `_PLAN_CAR`，性格切换、偏好修改、方言请求也依赖正则 | 没覆盖的说法失灵，覆盖到的又僵硬；越往后越难维护，也越像“规则机” |
| 人格只写“怎么说话” | `config/personas.toml` 六种是表达风格；`persona.py` 核心提示词大量是“不要……”约束 | 没有会变的心情、自己的经历和被记住的观点；“不虚构亲身经历”必须保留，结果是她只能聊对方 |
| 记忆偏“用户档案” | 已有 `semantic/persona/episodes` 作用域，但抽取以用户偏好和事实为主；“待续话题”只有看车这一个特例 | 缺“我们一起经历过什么”“上次没聊完什么”“她今天见了谁、看到什么” |
| 主动性靠定时器 | 空闲 60 秒、续聊 15 秒后由 LangGraph 判一次要不要说（见[三层交谈机制](../开发记录/2026-10-09/三层交谈机制.md)） | 人开口是因为有话想说，不是因为过了 N 秒 |
| 没有活人感回归 | 每次改提示词只能等下一次现场演示发现问题 | 改一处坏一处，无法放心删正则 |
| 主链文件过大 | `apps/runtime/src/annie_runtime/realtime.py` 约 4366 行，`__init__.py` 约 2713 行 | 后续每个改动的定位和回归成本持续上升 |

## 4. 活人感拆成五件事（按投入产出排序）

所有方向都遵守现有约束：普通聊天不经过 LangGraph、不新增常驻 sidecar、新增模型调用不进首响主链、新增模块须回答 PROJECT_RULES 的四个问题。

### 4.1 先建评测闭环（前提）

- **做什么**：把 `docs/运行日志/` 已导出的真实对话整理成回放集，逐句标注“该不该回、接没接住、记没记得、像不像她、有没有重复/说教/机械”。用大模型按维度打分，人工抽检一部分。改提示词、换模型、删正则前先跑这套。
- **挂在哪**：新增一个显式执行的评测脚本（调用真实 Provider，不进默认 `pytest`，不依赖根 `.env` 才能跑默认回归），结果写入 `docs/开发记录/<日期>/`。d3 评测的方法直接扩展过来。
- **验收**：同一套样本、固定模型和参数下能复跑并给出各维度分数和逐句差异；至少覆盖最近三次现场演示的原话。
- **收益**：有了它，才能把正则一条条换成模型判断而不怕回退。

### 4.2 真实经历与关系记忆

- **她自己的经历日志**：今天见了谁（人脸库认出的人）、聊了什么话题、被摸头/按压、看到了什么。全部来自真实事件，所以她能说“今天上午有个小朋友一直戳我”，既不违反“不虚构经历”，又有生活感。
- **待续话题**：对方说过要去做、还没结果的事，下次见面自然问起。用一个通用机制取代 `_PLAN_CAR` 这类特例，带来源轮次、有效期和“已结束”状态。
- **每晚反思**：后台用 LangGraph 把一天的经历压成少量印象（对这个人的看法、两人关系、她最近在意的事），下次会话开始时随 Persona/记忆一起有界注入。这正是慢脑该做的事，不碰实时链。
- **隐私边界**：只对已认出的人（人脸/声纹）提起与他相关的待续话题；公共场景和 8C 空闲搭话继续不说私人内容。
- **需拍板**：经历日志保存哪些内容、保存多久；展厅等公共场景是否完全关闭。

### 4.3 会变的内在状态

- **做什么**：一个很小的结构化状态，比如心情、精力、好奇心、对眼前这个人的熟悉度。随事件变化、随时间慢慢回落，有来源和版本。
- **作用**：决定性格表现强弱（累了话少一点）、TTS 情绪、要不要做自发表情；替换一部分 `SOCIAL_HINTS` 加正则的工作。
- **约束**：它属于 PROJECT_RULES 里的“轻量 SocialState”，不是新情绪模型，也不每轮重发完整 Persona。

### 4.4 主动开口：从定时器改成“心里有话”

- **做什么**：维护每个机器人的“想说的话”候选池，来源是熟人出现、待续话题、时间（饭点、晚上）、传感器事件和她自己的经历；每条带“想说的程度”分数和过期时间。
- **怎么接**：沿用 `IdleService` → `SpeakRequest` → Speak Policy → TurnCoordinator，分数够、时机对才开口，否则保持安静。现有“有人对话时不打招呼”“同一人冷却”等规则继续有效。
- **参考**：Inner Thoughts（隐藏想法流 + 内在动机打分）。

### 4.5 倾听时身体也要“活着”

- **做什么**：对方说话时看向他、在停顿处点头、表情跟着内容变；空闲时有呼吸感、偶尔看别处。用本地规则驱动，不走大模型，不加首响延迟。
- **依赖**：需要嵌入式确认可用动作（点头/注视/呼吸）、触发延迟和 `action_trigger` 回执；Runtime 只按 VAD/起声事件和视觉位置下发。
- **谨慎**：语音附和（“嗯”）会和回声消除、打断判断冲突，先做不出声的部分。
- **参考**：有研究显示带积极倾听反馈的机器人让人更愿意多说（65 人实验）。

## 5. 不建议做的

- 再加 Agent 或 Graph 节点来“显得聪明”；
- 继续往提示词里叠禁止条款，或为单个案例加正则；
- 为了像人编造经历、共同回忆或设备能力；
- 追求一直在说话。知道什么时候不说，本身就是活人感；
- 现在换端到端全双工语音模型。它们在中文、工具调用、嘴型可控上都还不成熟，保持观察即可。

## 6. 需要用户拍板的问题

1. PROJECT_RULES 写了“不靠额外情绪模型”。如果想用语音情绪识别（如 emotion2vec+ / SenseVoice）给内在状态提供声学证据，需要先改这条规则。
2. 经历日志和待续话题的保存范围、期限，以及公共场景是否关闭。
3. 倾听动作需要嵌入式哪些动作和回执，由谁排期。
4. 解冻后先做哪一项。建议先做 4.1 评测闭环，后面几条好不好都要靠它判断。
