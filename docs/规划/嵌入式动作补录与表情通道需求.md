# 嵌入式动作补录与表情通道需求（2026-11-20，供与嵌入式同步）

## 一、背景与现状

- 主脑按 `script_id` 触发嵌入式录好的动作（`action_trigger`），目录见 `config/action_scripts.json`，现有 39 个：主要 23 个（0.85～6 秒）、特殊 3 个、微动作 13 个（0.5～0.95 秒）。动作本体（关键帧、舵机角度）都在嵌入式，主脑只知道编号、名字、描述和时长。
- 现在会自动做动作的时刻：
  - 用户开口约 0.7 秒：倾听 / 附和小点头 / 侧耳听 / 轻歪右 挑一个；一直在说时每 6 秒左右再一个；说话停顿时附和点头；她要想一会儿时眼睛往上瞟。
  - 她说话时：每句由决策模型从 10 个里挑一个或不配，每次回复最多 3 个。
  - 说完后心情变化明显时一个反应动作；被反复碰时不出声只做小动作；用户点名要的动作照做。
- 问题：11 月 962 次回复里只有 249 次配了说话动作（平均 0.27 个），四分之三一个都没有。可选的多是 1～6 秒的长动作，频繁做显得夸张，所以几乎不选；缺少零点几秒、每句都能用的“说话节拍”小动作。
- 11-20 起她会笑出声、叹气、倒吸气、哼，并能用好奇、调皮、难过、生气等整句语气，但动作表里没有“笑”这类表情，脸上配不上。

## 二、需要补录的动作

建议 `script_id` 仅供参考，可按嵌入式命名规范改，交付时告诉我们最终 id 即可。

### A. 说话节拍（优先级最高）

## 三、通用录制要求

1. 时长尽量贴近表中数值，交付时给出实际 `duration_ms`。
2. 结束时回到中立位，下一个动作可以紧接着开始。
3. 节拍类和表情类在她说话时也要能做，不能干扰嘴型舵机。
4. 幅度宁小勿大；说话和听用户说话时做的动作，电机声越小越好（影响收音和回声消除）。
5. 新动作来时能打断正在做的动作；如果能叠加（比如眨眼叠在点头上）请说明哪些能叠加。
6. 每个动作给：`id`、中文名、一句描述（什么时候用）、`duration_ms`、类别（primary / micro / special），我们更新 `config/action_scripts.json`。
7. 设备回执照旧：开始 `device_started`、结束 `device_finished`。

## 四、主脑这边怎么用（动作多了也不会全交给大模型挑）

- 节拍类（A）：按句子位置和语音的重读、停顿由程序配，决策模型只在少数几个里挑。
- 表情类（B）：由她回复里的笑声、语气标签直接对应，不需要模型再选一次。
- 社交类（C）：由事件触发：有人靠近、被叫醒、说退下。
- 触摸类（D）：由传感器事件触发，按部位选。
- 每个场景给决策模型的候选控制在 10 个以内；接入前会用往期对话回放测选择准确率。

## 五、需要嵌入式回答的问题

1. 现有 39 个动作的关键帧能否导出（每个时间点各舵机角度，JSON 即可）？用于让大模型离线帮忙设计新动作，以及以后做连续控制。
2. 各关节有哪些、角度范围、中立位、最大速度 / 加速度？
3. 两个动作能否叠加？新动作到来时旧动作是立即打断、平滑过渡还是排队？
4. 能否支持“保持”类动作（进入后保持，收到退出指令再回中立）？
5. 说话和听的时候做小动作，电机声对麦克风收音的影响有多大？
6. 从收到 `action_trigger` 到电机开始动，一般延迟多少毫秒？

## 六、后期可选：连续表情姿态通道

现在的方式是“按编号放一段录好的动作”。如果嵌入式能开一条连续通道，主脑每 50～100 毫秒发一次头（三轴）、眼球、眉、眼皮的目标位置，嵌入式负责插值、限位、限速，就能做到：

- 视线跟着说话的人（视觉给人脸位置，头和眼睛实时转过去）；
- 跟着她说话的重音、停顿、语调做微动作，句尾眨眼；
- 同一表情调强弱，动作之间平滑衔接、可叠加；
- 反应更快，不用等脚本播完或冷却。

需要嵌入式确认：能否做、更新频率、从收到到执行的延迟、安全限位放在哪一层。这项不急，先把第二节的动作录好，脚本方式还能走很远。
