## 1. 视觉题先应一声（`[vision.intent] ack = true`）

改动前：判为视觉题后整轮回复先压住，转头（回执正常 2.0～2.5 秒才到，动作表写 1.3 秒）、看图（云端中位约 2.0 秒）都完成了才开口；11-10～11-18 视觉题从云端判停到扬声器出声中位 4.4 秒、P95 7.1 秒，期间一句话都没有。

现在：
- 判为视觉题后，立即转头（不变），同时给实时模型加一条只管这一句的临时指令【先应一声】：用当前性格自己的说法说一句十个字以内的短话，每次不一样，不说看到了什么、不猜画面、不调用工具。走原有 TTS 和嘴型，整轮还是同一个回合。
- 新画面回来后撤掉临时指令，换成【刚才已经应过一声】（避免再说“我看看”），再请实时模型接着答；回答结束后这条也撤掉。
- 云端抢先生成的那条回复仍然作废；它还没结束（1 秒内）、用户又开口、或画面先到了，就不再应声，照旧直接回答。
- 用户在她应声时插话，按原插话规则作废这一问，临时指令立即撤掉，不会带到下一句。
- smart_turn 丢掉又补回来的视觉问题也会先应声，用户原话只补发一次。
- 开关：`config/runtime_defaults.toml [vision.intent] ack`；`.env` 的 `ANNIE_VISION_ACK_ENABLED=1/0` 覆盖。

注意：视觉题的分轮“首字/首包/扬声器出声”现在量的是这句过渡语；看图后正式回答的等待看 `vision_intent` 行的 `total_ms`。

## 2. 新画面后回答抓重点，不再二次 look_closely

11-10～11-18 拿到新画面的 110 个视觉回答里，36 个（33%）又调了 `look_closely`：每次多一轮工具往返（约 0.8 秒），拿回来的还是每秒一条的旧本地画面，和新画面打架（#2281）。原因是基础视觉规则写着“问到穿着、长相……先调用 look_closely”，和新画面那条“不用再调用”冲突。

- 有新画面时，基础规则里这句不再出现；新画面那条改为“不要再调用 look_closely”，并要求先说和问题最相关、最显眼的一两样，再带半句自己的反应，细节等追问（对应 #2290 报菜名）。
- 万一还是调了，`look_closely` 结果里带上这份新画面（`fresh_view`），物体和场景以它为准，认人仍按本地画面的 who。

## 3. 同类刺激逐次降级（`[events.habituation]`）

11-16 16:20 起 6 分钟里有人 15 次靠近，她 15 次都在抖机灵；11 月 943 轮里 299 轮（32%）是传感器或主动搭话触发的。

- 同一处触摸/按压（额头、鼻子、脸颊、肩膀、头顶分开算）、雷达“靠得很近”、气味：第 1 次照常说；第 2 次在提示里要求只用几个字随口应一下；第 3 次起不出声，只做一个小动作（触摸：害羞/连眨两下/轻歪头/坏笑；靠近：连眨两下/眼瞟下/轻抬下巴；气味：嗅闻/怀疑/连眨两下，按动作白名单放行，同一机器人 4 秒内最多一次，她在说话或休眠时不做）。
- 这类刺激停 120 秒（`quiet_seconds`）后再来，又当新鲜事；用力按（4 级以上）最多降到“几个字”，不会只动不说。
- 换部位不受影响，所以“拍肩→摸额头→摸脸”这样轮流演示每处都会正常回应；同一处 2 分钟内连拍会先变短、再只做动作。
- 降级的事件照样更新心情；不出声的那次不进对话轮次。工作台外部事件里显示为 `habituated / observed · habituated`。

## 4. 退下后空闲搭话也安静

#2177（11-14 16:51:22 “小爱你退下，小爱你别说话”）之后 110 秒，空闲主动搭话（8C）自己开口说了 #2179。“心里有话”那条路早有 30 分钟静默，空闲搭话没有。现在空闲搭话同样在“退下/闭嘴”后 30 分钟内不开口（原因记为 `asked_to_be_quiet`）。触摸等外部事件按 11-18 “外部事件优先”的决定照常回应，没有改。

## 5. 判停时序日志

以前日志里的 endpoint 是云端 `speech_stopped`，已经在判停之后，判停本身（10-13 实测约 0.8 秒、11-05 实测中位 1.44 秒）不在任何日志里。现在每帧上行 PCM 记下发送时刻和本地音量（与倾听点头同一套噪底跟随），云端事件里的 `audio_start_ms/audio_end_ms` 换算回本地时刻：

| 日志 | 字段 | 含义 |
| --- | --- | --- |
| `speech_vad … event=started` | `start_lag_ms` | 云端认定的起声点那帧发出后，多久才发 `speech_started` |
| `speech_vad … event=stopped` | `speech_ms` | 云端认定的这段话长度 |
| | `endpoint_ms` | 云端认定的结束点那帧发出后，多久才发 `speech_stopped`（纯云端判停耗时） |
| | `voice_end_to_stopped_ms` | 本地听到最后一帧人声 → 云端判停（用户实际等的判停时间） |
| | `audio_end_after_voice_ms` | 云端结束点比本地最后人声晚多少（可为负） |
| | `floor_dbfs`、`her_voice`、`invalid`、`state` | 本地噪底；判停时她是否在说话（插话时本地人声可能混了她的声音）；是否 turn_invalid；唤醒状态 |
| `turn_latency` | `voice_end_to_endpoint_ms`、`provider_endpoint_ms`、`voice_end_to_first_text_ms` | 同上，按回合 |
| `speaker_latency` | `voice_end_to_speaker_start_ms` | 真实沉默：用户说完 → 扬声器开始出声 |
| `vision_ack` | `status`、`chars`、`ack_ms` | 过渡语是否说出、字数、请求到说完的耗时 |

分轮时间线（工作台“原始时间戳 / 耗时”）同步新增 `voice_end_ms`、`provider_end_sent_ms` 及对应耗时，延迟窗口新增 `voice_end_to_endpoint_ms`、`voice_end_to_speaker_start_ms` 的 P50/P95。本地人声用的是麦克风电平，展厅噪声大时最后人声可能偏晚，分析时结合 `floor_dbfs` 看。

## 6. 实时会话热词

`config/providers.toml [realtime.hotwords]`：小安妮（5）、四种性格名、21 种方言名（3）。只影响输入转写（唤醒、退下、方言、性格等规则用的是转写），不改变实时模型自己听到的内容——#2120 转写本来就是“河南话”、是模型自己听成“荷兰话”，热词救不了那种。权重 1～5，50 为超级热词（最多 50 个），人名可按需加。启动时校验，不合法直接报错。11-19 用真实接口探过：`session.updated` 回显了 `corpus` 里全部 27 个词，转写模型不变。

## 7. 计划里有、这次没做的两项

- **回执不白等**：日志里 `look_*` 的 `finished` 回执在 2.04～2.49 秒到（动作表 1.3 秒），超时那批在 2.5 秒放行，只比正常回执多等约 0.35 秒；按动作表时长取帧会在头还没转到位时拍照。保持不变，用第 1 节的过渡语盖住这段。
- **决策置信度门槛**：25 条决策样本里，“后面还有和尚”0.64（不该看）、“你看那个眉毛也不对”0.45（不该看），而“看一下，我伸出了几根手指头”只有 0.29、“我是谁呀”0.31（该看）；任何门槛都会拦掉该看的演示问题。留到第二批用标注数据改判断本身。
